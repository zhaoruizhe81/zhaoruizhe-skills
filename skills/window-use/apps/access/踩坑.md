# Access 2016（Office16）自动化踩坑 — 2026-10-26 花店销售管理系统实战

实付环境：windowpc（192.168.1.142），桥 PtGuiBridge，Access 2016 中文版，
桥端 pythonw 为 D:\software\miniconda\pythonw.exe（pywin32 3.13 已装）。

## A1. COM 自举：GetActiveObject 必失败，Access 随 pythonw 退出而关闭
- **症状**：`win32com.client.GetActiveObject("Access.Application")` 报
  com_error(-2147221021 操作无法使用/MK_E_UNAVAILABLE)；上一脚本打开的 Access 在
  pythonw 正常退出后进程消失。
- **原因**：DispatchEx 启动的 Access 不注册 ROT；且客户端进程退出释放引用后，
  UserControl=False 的 Access 自动退出。
- **解法**：每个驱动脚本自举——`taskkill /F /IM MSACCESS.EXE`（清残留，防多实例抢文件锁）
  → `DispatchEx("Access.Application")` → `Visible=True` → `OpenCurrentDatabase(DB, False)`
  → 干活 → 截图。脚本退出 Access 自动消亡，无实例堆积。绝不依赖跨脚本附着。
- **推论**：复杂对象（多窗体）**一个脚本一个全新会话**，连续 CreateForm/Close/Rename
  数轮后第 3~4 次 CreateForm 会"服务器出现意外"(-2147417851)甚至**无限挂起**（挂起还会
  占住计划任务 IgnoreNew，后续 /run 全静默跳过，见 远§4）。

## A2. CreateControl / CreateReportControl 真实签名（没有 ControlName 参数）
- **症状**：`app.CreateControl(表单名, "lblTitle", 100, 0, "", x, y, w, h)` 报
  `ValueError: invalid literal for int() with base 10: 'lblTitle'`。
- **原因**：真实签名为 `CreateControl(FormName, ControlType, Section, [Parent],
  [ColumnName], Left, Top, Width, Height)`——第 2 参就是 ControlType(int)，
  控件名自动生成；"找不到成员/找不到引用的窗体'报表1'"则是把 CreateControl 用在了报表上。
- **解法**：
  - 窗体用 `CreateControl`，**报表必须用 `CreateReportControl`**（同签名）。
  - 绑定字段走 ColumnName 位或事后 `ctl.ControlSource = 字段`。
  - 报表页眉/页脚节默认不存在：报表在设计视图下 `DoCmd.RunCommand(37)`（acCmdReportHdrFtr）
    增加报表页眉/页脚节，之后才能往 Section 1/2 放控件（"您所输入的节数无效"=节不存在）。
  - 新建报表主体节高默认 5952 缇（≈10.5cm 巨高），必须
    `app.Reports(临时名).Section(0).Height = 420` 压回（注意用 typed 句柄，见 A3）。

## A3. makepy 类型包装丢子类属性：统一 dyn() 转动态
- **症状**：EnsureDispatch 后 CreateControl 返回 `_Control` 基类，`lbl.Caption` 报
  AttributeError；`rpt.Section(0)` 动态句柄报"找不到成员"。
- **解法**：控件/窗体对象一律 `dyn(c)`（`win32com.client.Dispatch(c._oleobj_)`）后操作；
  节高等属性走 typed 路径 `app.Reports(名字).Section(0)`（app 为 EnsureDispatch 句柄）。

## A4. DAO 要点（实付三发）
1. **字段自定义属性必须入库后再挂**：InputMask/ValidationRule 等在 `TableDefs.Append(td)`
   之前 Append 属性会报 3219 无效操作。顺序：建字段→建主键→Append 表→Refresh→
   用 `db.TableDefs(名).Fields(字段)` 挂属性（CreateProperty+Append）。
2. **Jet 拒绝关联聚合子查询 UPDATE**（3073 操作必须使用可更新的查询）：
   `UPDATE t INNER JOIN (SELECT ... GROUP BY)` 不行——在 Python 里算好逐行简单 UPDATE。
3. **日期一律传字符串** "YYYY/MM/DD"：pywin32 把 naive datetime 按 UTC 平移，落地值
   偏移 8 小时（10-18 00:00 变 10-17 16:00）。

## A5. 数据表视图验证规则：静默拒绝，没有弹窗
- **症状**：想截"违反验证规则"的原生对话框——粘贴或键入非法值后单元格变粉色/红框、
  焦点被静默困住，记录存不进（DAO 复查值未变），**任何对话框都不弹**；
  回车/点别的单元格都无响应表现。
- **解法**：别恋战弹窗（实付 5 轮）。证据改用两件套：①设计视图字段属性特写
  （验证规则/验证文本可见）；②数据表视图中非法值被拒的无效态特写（+DAO 复查值未变）。
  同理**不要指望**页面页脚的 `=Sum()`（会显示 #错误）——合计必须放报表页脚（先 RunCommand(37)）。

## A6. 参数查询等模态对话框会阻塞 COM 调用
- **症状**：`DoCmd.OpenQuery(参数查询)` 不返回，驱动脚本卡死（pt.py TIMEOUT）。
- **解法**：模态交互（参数框、切换面板管理器 RunCommand(521) 等）一律两段式：
  段1 COM/GUI 触发（预期超时）→ ssh `taskkill /F /IM pythonw.exe`（MSACCESS 会话存活，
  对话框留在屏上）→ 段2 纯 GUI 脚本点击/粘贴（**不要 boot_access**，会连 Access 一起杀）。
  参数框输入用 paste_at（坐标从现场截图读）。
- **切换面板速成**：RunCommand(521) → 首启对话框点"是"创建默认切换面板 → 关闭管理器 →
  DAO 直接写 `Switchboard Items` 表（字段：SwitchboardID/ItemNumber/ItemText/Command/Argument；
  Command：2=添加模式开窗体 3=编辑模式开窗体 4=打开报表 6=退出；ItemNumber=0 行是标题行，
  ItemText 即面板标题）→ `db.Properties("StartUpForm")="切换面板"` 设启动窗体。
  比逐条点管理器对话框省 10+ 轮。

## A8. COM/DAO 建库速成（2026-10-27 电费收费管理系统实战）
- **场景**：从零建 .accdb（多表+主键+外码关系），不想点 GUI。
- **配方**：桥端 pythonw 直接 `Dispatch("DAO.DBEngine.120")`（实测可用）→
  `dao.CreateDatabase(path, ";LANGID=0x0804;CP=936;COUNTRY=0")` →
  `td = db.CreateTableDef(名)`；`td.CreateField(名, 类型)`（dbText=10 要再赋 `.Size`）→
  `idx = td.CreateIndex("PrimaryKey"); idx.Primary = True` → `db.TableDefs.Append(td)` →
  关系：`rel = db.CreateRelation(名); rel.Table/ForeignTable; rel.Attributes = 0（强制参照完整性）;
  rf = rel.CreateField(字段); rf.ForeignName = 字段; rel.Fields.Append(rf); db.Relations.Append(rel)`。
- **外码字段长度必须与父表主码一致**，否则建关系失败。
- 验证：重开 `dao.OpenDatabase` 遍历 TableDefs/Relations 写 txt 拉回，肉眼+程序双通道。
- 全程零 GUI，一轮 ~25s；比手点设计视图快一个量级。

## A9. 信任位置免"启用内容"安全条（registry 法）
- 中文 Office 对非信任目录的库每次打开都弹黄色安全条，污染截图。
- 桥端脚本里 `reg add "HKCU\...\Office\16.0\Access\Security\Trusted Locations\LocXxx" /v Path /d "<目录>\" /f`
  （**尾随反斜杠必须带**），再 OpenCurrentDatabase 即无安全条，且持久生效。

## A11. MSGraph 图表窗体：程序化嵌入全灭，唯一活路 = GUI 图表向导（实付 8+ 轮）

- **向导两段式全流程坐标**（1920×1080，最大化，窗体设计视图）：
  控件库下拉 (1103,128)；展开后 **超链接=(231,152)、图表=(268,152)——按图标认，勿按位置**；向导页：查询radio(952,482)、Q5列表行(900,403)、>>(1090,384)、下一步(1180,650)、完成(1281,650)、标题框(990,303)；视图按钮(40,125)会弹**下拉菜单**，窗体视图(F)菜单项=(99,182)。

## A12. 顶层窗体数据表视图列头空白：挂附加标签
- **症状**：控件只有 TextBox（tx.Name=字段名）时，子窗体嵌入场景列头显示字段名，但**顶层窗体/分割窗体数据表区列头全空白**。
- **解法**：每个字段挂附加标签 `CreateControl(窗体, 100, 0, 文本框名, "", x, 0, w, h)` + `lbl.Caption=字段名`；设计视图打开表单后逐个补（f02fix/f05fix2 模式）。按名找控件前确认控件真名（CreateControl 自动命名 Text12 之类，按 ControlSource 查找更稳）。

## A13. dyn() 必须 dynamic.Dispatch；Section/Module 兼容
- gen_py 类型包装三连坑：**Module 丢 InsertCode**（用 `InsertLines(1, code)` 兜底）；图表控件被错型 _ToggleButton 丢 .Class；`frm.Section(0)` 报 MEMBERNOTFOUND（改 `frm.Detail.Height`）。
- 统一解法：`dyn()` 内用 `win32com.client.dynamic.Dispatch(c._oleobj_)`，绕开 gen_py。
- **VBE 通道可用**（此机已开 VBA OM 信任）：app.VBE → VBComponents.Add(1) → CodeModule.AddFromString → app.Run——注入函数内可用 Access 原生常量（acOLECreateEmbed 等）与 DeleteControl 语句；重复注入前先删旧 Module* 组件防重名。

## A14. 远程 Git Bash 本身也会做路径转换
- 本地 `MSYS_NO_PATHCONV=1` 管不到**远端** Git Bash：`ssh windowpc "taskkill /F /IM x"` 报 'F:/' 无效参数，`cmd /c "taskkill ..."` 嵌套引号被吃只回显 banner。
- 统一解法：printf 写 .cmd 文件 → `MSYS_NO_PATHCONV=1 cmd /c C:/Users/master/xxx.cmd` 执行（killpw.cmd/fixtrust.cmd 模式）。
