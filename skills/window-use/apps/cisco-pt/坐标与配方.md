环境基准：PT 8.2.0，1920×1080，100% DPI，窗口最大化，中文输入法可能开着。
**新 PC / 新分辨率首跑必须 `ptlib.probe()`**（画准星不点击，拉回截图对照）。

## 坐标体系（比例化 + 锚点）

绝对像素坐标换屏幕就作废，所以一律存成"规格"，运行时按实际分辨率解析：

| 锚点 | 格式 | 含义 | 适用 |
|---|---|---|---|
| `r` | `("r", rx, ry)` | 屏幕宽高比例 0..1 | 画布内容（设备位置）、随窗口拉伸的区域 |
| `bl` | `("bl", px, dy)` | 左缘像素 + 距底像素 | **贴底停靠的组件面板**（图标大小不随分辨率变，纯比例会偏） |
| `c` | `("c", dx, dy)` | 屏幕中心偏移像素 | **居中弹出**的对话框/控制台 |
| `tl` | `("tl", px, py)` | 左上固定像素 | 贴边固定像素工具条（**PT 大量使用**：设备图标行、Simulation/Filters 按钮区等） |

为什么不是纯比例：调色板贴底、图标是固定像素大小，1080p 的 y=945 换到 1440p
按比例算会偏 40+ 像素直接脱靶；按"距底 135px"算则分毫不差。对话框同理是居中定宽窗。
center 类坐标（`c`）是否真居中未在第二块屏幕验证过——probe 一眼便知，偏了改数字即可。

## 操作粒度表（原子步进协议 · 一次触发做多少）

skill 工作流规定"一次触发 = 一个原子动作 + 一次验证"。本 app 各动作的粒度（实测依据）：

| 动作 | 一次触发做多少 | 依据 |
|---|---|---|
| **连线** | **一条，铁律**（`ptlib.wire` / `ptlib.wire_uia` 第二次调用直接 raise） | 批量 B 端菜单必炸，见 踩坑.md |
| CLI 配置 | 一台设备的全部命令行（`cli_config` / `router_cli_config`） | 粘贴型，实测稳 |
| 放设备 | 可一批多台，但**每台改名后截图核对** | 改名随机失败 |
| PC 配 IP | 一台（贴字段 + 截图核对；字段坐标会话内会漂移） | 踩坑.md |
| ping 验证 | 一对（结果看截图判读；**等统计行出来再截**，~9s/ping） | 踩坑.md |
| 路由器装模块 | 一台（关电→拖→开电→关框→等启动→Config 树验证） | 踩坑.md 2911 段 |

多条连线的循环放在 **Mac 端编排**，不写进 PC 脚本：
`push w01.py → send script w01.py → pull 截图 → 看图 → 下一条`（见 脚本用法.md）。

## 配方（函数体都是实战验证过的，在 ptlib.py）

```python
import sys; sys.path.insert(0, AUTO + r"\apps\cisco-pt")   # 驱动 script 环境内
import ptlib as pt

# 放置 + 改名（放置工具一次性，palette 内部每次重选）
pt.place("cat.end", "icon.pc", pt.LAYOUT_LAB2["PC12"])
pt.rename_device(pt.LAYOUT_LAB2["PC12"], "PC12")

# 连线——一个脚本只连一条（原子步进铁律；连下一条另起一次触发）。
# 慢点击版：黄定位菜单项 + moveTo 悬停 + 按下释放（见 ptlib.wire/port_click）。
# 端口用"菜单序号"：PC 的 Fa0=0；2960 的 Fa0/1、Fa0/2=0、1；Router-PT 的
# Fa0/0、Fa0/1、S2/0、S3/0=0、1、2、3
pt.wire("icon.straight", pt.LAYOUT_LAB2["PC12"], 0,
        pt.LAYOUT_LAB2["SW4"], 0)          # PC Fa0 ↔ SW Fa0/1（本脚本到此为止）
# 下一条线（串口例：先点的端 = DCE，要配 clock rate）写在 w02.py，重新触发：
# pt.wire("icon.srlDCE", pt.LAYOUT_LAB2["SW4"], 2, pt.LAYOUT_LAB2["SW5"], 0)

# 千兆口路由器（2911 等）连线必须用 UIA 按名版——Gi 插头不是黄色，
# wire() 的像素锚找不到。端口名以菜单实际显示为准（2911+HWIC 装哪个槽叫什么）：
# pt.wire_uia("icon.srlDCE", RTB, "Serial0/3/0", RTA, "Serial0/3/0")  # 先点端=DCE

# 交换机批量 CLI（粘贴行 + 自动保存 + 截图）
pt.open_device(pt.LAYOUT_LAB2["SW4"], "cli")
pt.cli_config(["enable", "configure terminal", "vlan 10", "name VLAN10", "end"],
              shotname="sw4_vlan")

# PC 配 IP（先进 Desktop→IP Configuration 窗口，再贴字段）
pt.paste_field(pt.COORDS["dlg.ipv4"], "192.168.10.12")
pt.paste_field(pt.COORDS["dlg.mask"], "255.255.255.0")
pt.close_dialog()

# PC ping 验证（自动先 arp -d 清残留；结果看截图判读）
pt.open_device(pt.LAYOUT_LAB2["PC12"], "desktop")   # 之后需点开 Command Prompt
pt.pc_ping(pt.LAYOUT_LAB2["PC12"], "192.168.10.13")
pt.shot("pc12_ping")

# 删设备（DEL + 居中确认框）
pt.delete_device(pt.LAYOUT_LAB2["PC16"])
```

## 2911 路由器专项（Lab4 v2 实战验证）

现代路由器（2911/4321 等）和 Router-PT/1841 的差异，全都在 踩坑.md 有完整因果：

- **选型**：Network Devices 面板滚到最左时 2911 图标在 `icon.rtr2911`（tl 384,940）；
  面板没有 2811（到 2620XM 就没了）；Miscellaneous 行也有 2811/2911/2960 快捷图标。
- **串口**：一张 HWIC-2T 插进哪个物理槽，端口就叫什么（本次插进 slot 3 →
  `Serial0/3/0, Serial0/3/1`）——**以 Config 树/端口菜单实读为准，别假设 0/0/x**。
- **装模块配方**（一台一次触发）：开框 → Physical 标签(`dlg.tab.physical`) → Zoom In
  (838,268) → 视图竖滚动条(x≈1278)拉到底 → 点前面板电源 (947,578) 关电 → 拉回顶部 →
  拖 HWIC-2T 列表项 (674,288) → HWIC 槽 (855,325) → 拉到底点电源开电 → 关框 → 等 ~45s。
  验证：重开 Config 树看串口出现。
- **连线**：Gi 插头不是黄色 → `pt.wire_uia(...)`（按端口精确名点菜单）。
- **CLI**：`pt.router_cli_config(dev, lines, shotname=, verify="show ip route static")` ——
  自带净场（先 `close_leftovers()` 关上一轮残留对话框，否则画布点击会落进旧对话框，
  配置粘错设备）、初始对话框守卫、模式恢复、路由行慢速粘贴。
- **看路由表**：PT 的 IOS 没有 `terminal length 0`；`--More--` 回车只翻一行，输出超屏后
  尾行（S* 行）不可靠 —— 要看 S* 默认路由用 **`show ip route static`**（一屏放下）。

## 配方：报文面板捕获全流程（Lab5 v2 实测 100% 跑通）

```python
# 前提：Realtime 已验证连通；PC 里 arp -d 过(或不需要)；PT 已进 Simulation 模式
# 1) 过滤器只留需要的协议(如 TCP+HTTP：去掉 ARP/DNS 省渲染；DNS 会话则用 IP 直访绕开 DNS)
# 2) 关所有设备对话框 → sim.reset → 2s
# 3) PC 浏览器 Go（IP 直访 http://202.118.100.25 可跳过 DNS）
# 4) 循环 N 次：sim.forward；每 0.65s；弹出蓝 i 图标 = 会话结束/缓冲满 → View Previous
# 5) 滚动条轨道拖拽翻页找目标行（Times 从小到大）
# 6) 目标行：单击一次 → sleep 1.2s → 四连拍：
#    OSI 全屏图 → tab_in 双击 → 详情顶部图 → 详情区拖动 → 详情底部图
# 7) 素材验收：每张裁 pdu.region 确认含 At Device/Source/Layer 文本，才算拍到
```

**行定位锚点法**（点击会触发自动滚动，y→行映射不可预算）：
先点一个内容已知的行（如列表末尾 SRV3 行）→ 再点目标行（连续两次"切到新行"，无 toggle）→
标题条截图确认 At Device/Source。找纯 ACK 行是徒劳的（PT 只渲染 L2，见踩坑.md）。

## 粒度表追加（仿真模式）

| 动作 | 一次触发做多少 | 依据 |
|---|---|---|
| 步进 Capture/Forward | 可一批 40-50 次（每 0.65s，无截图） | 纯推进无状态交互 |
| 行点击+面板四连拍 | 一行一次（含 1.2s×3 渲染等待） | 渲染延迟 ~1s，快了全是废片 |
| Buffer Full 处理 | 一次弹窗一次点击（立即） | 弹窗吃一切后续点击 |
