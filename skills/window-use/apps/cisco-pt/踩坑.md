# Packet Tracer 私有坑（公共坑见根目录 踩坑清单.md，远程坑见 remote/远程坑.md）

每条都是实战付出过排障时间的。症状 → 解法。

## Qt 菜单与连线（Lab4 实战新增，最贵的一批）

### 批量连线必炸 B 端——一条线一次触发（铁律，ptlib.wire 已内置强制）
- **症状**：一个脚本里 `pt.wire()` 连调多次：第一条往往成，之后的线 A 端菜单照常弹出、
  选口正常，点第二台设备时端口菜单**必现不弹**，port_click 重试也救不回。换自动选线
  （闪电，完全绕开菜单）同样一条都连不上。同一 session 内"单线单脚本"5/5 全成。
- **规则**：**一次驱动触发只连一条线**（skill 原子步进协议的 cisco-pt 粒度，见
  坐标与配方.md 粒度表）。连下一条 = 重新触发一次脚本。`ptlib.wire()` 第二次调用直接
  raise 提醒（确要连多条传 `force=True`，后果自负）。
- **原因（候选，未定位死）**：上一步残留状态吸收点击——刚关闭的 QMenu 的鼠标捕获/
  工具状态未冷却，或崩溃残留现场；单次触发自带 ~15s 冷静期恰好躲开。开工净场
  （断言单实例 + 双 esc）后单线触发依然稳定，说明**守规则比查根因优先**。
- **教训**：连线是全部 PT 动作里唯一实测批量必炸的；不要试图在脚本里 for 循环连线，
  循环放在 Mac 端编排（一次一轮：push → send → pull 截图 → 看图 → 下一条）。

### Qt 端口菜单不接受"瞬移点击"——必须 moveTo 悬停后按下-释放
- **症状**：线缆工具选中后点设备弹端口菜单，黄定位算出的菜单项坐标完全正确，`pyautogui.click(x,y)` 点击后菜单纹丝不动（也不关闭）——端口永远选不上。
- **原因**：Qt 弹出菜单忽略"瞬移点击"（鼠标从别处瞬移过来立即按下-释放）；必须先把鼠标**移动到菜单项上**（触发 hover）再按下-释放。
- **解法**：`pyautogui.moveTo(tx, ty, duration=0.25)` → sleep → `mouseDown(); sleep; mouseUp()`。ptlib 的 `port_slow` 已实现。
- **教训**：凡 Qt 菜单/弹出项的点击，一律慢点击，不用裸 click。

### "菜单消失"≠"端口选中"，要验证线头真的挂上
- **症状**：点击菜单项后菜单关闭（fe_anchor 扫不到黄 → 误判成功），但线头根本没挂上，后续点第二台设备毫无反应。
- **原因**：点击可能落在菜单项的空隙/边框上，把菜单点关了而没选中端口。
- **解法**：选中判定改成"**菜单从屏幕上消失**且重试时重新点设备再触发菜单"；连线最终成败用**端到端检测**（两设备间出现连线/像素）确认，不信任中间步骤的"成功"。

### 脚本异常退出时，弹出中的 QMenu 会残留在屏幕上
- **症状**：一次脚本崩了之后，后续所有连线脚本的 menu_click 全部"成功"却毫无效果、坐标点击被莫名吸收。
- **原因**：崩溃时弹出的端口菜单还开着，后续 menu_click 点的全是这个残留菜单的项，坐标点击被它挡住。
- **解法**：每个连线/菜单脚本**开头连按两次 esc** 清残留菜单；FAIL 后重试前也先 esc。

### 底部 y > 0.85 的画布点击会被组件面板挡住
- **症状**：往画布底部放设备/点击，一部分成功一部分毫无反应。
- **原因**：组件面板窗口覆盖画布底部约 150px（y>930），点击落在面板上。
- **解法**：布局时所有设备保持在 y ≤ 0.84（1080p 下 907px）以内。

### 两个 Packet Tracer 实例并存 = UIA 和点击全错乱
- **症状**：连线脚本"成功"却无线、菜单扫不到、点击落点对不上——彻底的灵异现场。
- **原因**：桌面同时有两个 PacketTracer.exe（一个僵尸 + 手动新开的），UIA 枚举混到两实例的窗口，坐标点击落在**前台那个（可能是空白实例）**的画布上。
- **解法**：开工前 `tasklist | grep -i packet` 确认**只有一个实例**；多余的全部 taskkill（注意先保存内存中有进度的那个，进度只存在内存里直到 Ctrl+S）。

### PT 8.2 冷启动强制 NetAcad 登录，点 X = 直接退出
- **症状**：冷启动弹 "Cisco Packet Tracer Login"，点右上 X → "Login Failed. Cisco Packet Tracer is shutting down"，PT 整个退出。
- **解法**：登录框出现后**等 20 秒**，左下出现 Guest Login 按钮（倒计时结束才可点），点它以访客进主界面；或者登录一次账号（记住 3 个月）。别点 X。
- **附带**：PT 进程有时退出不干净残留进程，重启前 `taskkill /F /IM PacketTracer.exe` 全清。

## 组件面板

### Miscellaneous 面板的 "PC" 是假的
- **症状**：用它放的 PC 打不开 FastEthernet0（UIA 枚举端口菜单只有 RS232、USB0、USB1），连线失败。
- **解法**：一律用 End Devices 面板的 PC（`icon.pc`，坐标同为 (229,945)），它有 FastEthernet0。
- **教训**：长得一样的图标不等于同一个组件；怀疑时先 UIA 枚举端口菜单取证。

### 2960 交换机在 Miscellaneous 面板；Router-PT 在 Network Devices 面板
- 2960 图标 (389,940) 在 Miscellaneous；Router-PT (597,940)、Serial DCE 线缆 (509,940)、Serial DTE (549,940)——均已实测录入 ptlib.COORDS。**面板图标的归属和坐标必须用"点图标看底部状态栏文字"的方法确认**（点一下图标，状态栏显示工具名，100% 准确）。

### 放置工具是一次性的
- 从面板点一次图标只能放一台；连放多台时每台都要重新选（ptlib.palette 已处理）。

### 新路由器要等 boot 完才能开 Config（Lab4 复现确认）
- 放置路由器后立刻开 Config 会弹 "Device is still booting"，改名静默失败。放置后 sleep ≥30s 再改名，改完截图核对。

### 画布放置的点击在 y>0.85 或 y<0.13 区域会失败
- 顶部是工具栏+Logical/Physical 蓝条（y<150 不可点），底部是组件面板（y>930 不可点）。布局规划时避开这两条带。
### 单击设备 = 打开对话框，不是"选中"
- 想选中删除：单击（弹对话框）→ 关掉对话框 → 设备仍处于选中态 → 按 DEL → 居中确认框点 Delete。
- **右键设备没有上下文菜单**（删除/查看都走不了右键），别浪费时间试。

### 确认删除对话框在 UIA 里被拍平
- `Desktop.windows()` 找不到 "Confirm Delete" 窗口，只能用固定像素坐标点 Delete（`confirm.del`，居中模态）。

### 画面上有"叠罗汉"设备
- **症状**：点哪个位置弹出的对话框标题都是同一台（如 PC1），新放的设备不见了。
- **原因**：之前失败的放置把设备叠在了同一坐标，顶层挡住一切点击。
- **解法**：反复点同一位置看标题是否不变 → 确认叠放 → 全删掉重放。

## 控制台与输入

### PT 控制台（交换机 CLI）不认 Ctrl+V
- 只能点控制台自己的 **Paste 按钮**（`cli.paste`）；剪贴板文本末尾带 `\n` 会自动当回车执行。

### PC Command Prompt：Enter 会被中文 IME 吃成汉字
- 粘贴用右键 → Paste 菜单（`pc_paste`）；回车必须 `send_keys("{ENTER}")`（`pc_run`）。
- 若先按一下 Shift（切 EN）再操作更稳。

### --More-- 分页器吞命令
- `show` 类长输出停在 `--More--` 时，后续粘贴的整行会被当分页按键吃掉。
- **解法**：下一批命令前先贴一个 `q`（或回车）把分页冲掉再继续。

### 控制台历史跨关闭保留
- Command Prompt 关掉重开，历史命令还在——排障时别被旧输出迷惑，先 `arp -d` / 清屏。

### paste 后 DNS 翻译卡顿
- 控制台贴入残行可能触发域名解析尝试（卡 5~10 秒），批量配置开头先贴空行冲掉并留等待
  （`cli_config(flush=2)` 已处理）。

### 新交换机要等 boot 完成（第二次实战新坑）
- **症状**：放置交换机后立刻开 Config 改名，弹 "Device is still booting. Please wait until it is finished."
  小提示框，Display Name 粘贴静默失败，设备保持默认名（Switch1/Switch2…）。
- **解法**：放置后 sleep ~30 秒再动 Config；改名后截图核对名字。

### "叠罗汉"的像素检测清场（第二次实战新坑）
- **症状**：删除流程（DEL+确认框）某次没删成，新设备又放到同一坐标——两个设备叠着，
  线还挂在旧设备上，界面看不出来。
- **解法**：写 `has_device(spec)`：PIL 采样设备图标区域统计彩色像素（画布纯白），
  `while has_device: 删除流程`，删到检测为空为止。比人眼反复点开对话框核对快得多。

### IP Configuration 子面板位置不固定（第二次实战新坑）
- **症状**：按上次校准的绝对坐标贴 IPv4/掩码，值贴进了 DNS Server 框。
- **原因**：IP Configuration 是设备对话框内的浮动子面板，打开位置不保证一致，
  "对话框居中"的锚点假设只对对话框本身成立，对其内部子面板不成立。
- **解法**：每次会话开眼校准一次该面板字段坐标，会话内复用；贴完必须截图核对。

### EtherChannel 捆绑失败：成员口配置不一致（第二次实战新坑）
- **症状**：`%EC-5-CANNOT_BUNDLE2: Gi0/1 is not compatible with Gi0/2 ... (dtp mode of
  Gi0/1 is on, Gi0/2 is off)`，`show etherchannel summary` 长期 Po2(SD)、成员 (I)。
- **原因**：Gi0/1 之前手动配了 trunk，Gi0/2 加入 channel-group 时从 Po2 继承默认配置，两口不一致。
- **解法**：`no channel-group` 全拆 → `interface range gi0/1 - 2` 统一配 trunk → 再整体
  `channel-group 2 mode desirable`。另：协商要几秒，show 太早会误判 SD，等 5~10 秒再看。

### ping SVI 首包 timeout 是正常现象（第二次实战新坑）
- **症状**：PC 首次 ping SVI 显示 25% loss（丢第 1 包）。
- **原因**：首包用于 ARP 学习，不是故障。报告里注明即可，或 ping 两遍取第二遍。

## 网络 config 语义（PT 与真机的差异）

### Po1 上的 allowed vlan 不传播到物理成员口
- **症状**：EtherChannel 起来后（Po1 SU），在 Port-channel 接口配 `switchport trunk allowed vlan 10,20,99`，
  对端 ping SVI 全丢。
- **原因**：PT 里该命令不会下发到物理成员口 Gi0/1-2。
- **解法**：`interface range gigabitEthernet 0/1 - 2` 上显式再配一遍 allowed vlan。

### SVI 起不来（up/down）
- **症状**：`show ip interface brief` 里 Vlan99 协议态 down，ping 不通自己的 SVI。
- **解法**：`interface vlan 99` → `shutdown` → `no shutdown` 回收一次，Line protocol 立即 up。

### 换设备后 ARP 残留导致假丢包
- 删掉重连/换设备后 ping 100% loss，配置明明全对——PC 的 ARP 表里留着旧 MAC。
- **解法**：`arp -d` 再 ping（ptlib.pc_ping 已内置先清 ARP）。

## 路由器实验专项（Lab4 实战新增，最贵的一批）

### "Router-PT" 变体的 FastEthernet 口是坏的——换 1841 + HWIC-2T
- **症状**：铜线能接上（不报 Connection Error），接口 no shutdown 后永远 "up, line protocol
  down (disabled)"、0 包输入；PC/交换机都 ping 不通。换直通/交叉线都一样。
  有的 FE 口甚至直接拒绝铜线。**而画布链路灯会显示绿色** —— 别被骗。
- **解法**：删掉 Router-PT，换 **Cisco 1841**（自带 2 个铜 FastEthernet0/0、0/1，
  完美支持 PC/交换机接入），Physical 页拖一块 **HWIC-2T**（注意不是 WIC-2T）获得
  Serial0/1/0 + Serial0/1/1 两个串口。整台替换脚本化约 10 分钟。
- **实测接口名**：1841 = [Auxiliary, Console, FastEthernet0/0, FastEthernet0/1,
  Serial0/1/0, Serial0/1/1]；Router-PT 变体 = [Aux, Console, FastEthernet1/0,
  Serial2/0, FastEthernet4/0, FastEthernet5/0]（和想象中的 Fa0/0/Fa0/1/S2/0/S3/0 完全不同，
  UIA 枚举顺序 ≠ 视觉顺序）。**连线前先 dump 菜单拿真名**。

### 画布链路灯 LED 不可信——只有 ping 是真相
- **症状**：串口链路 up/up、ping 5/5，画布却显示红色；反过来也有真断链画绿的。
- **解法**：链路状态以控制台 `show ip int brief` + ping 为准；重启 PT / 重开文件 /
  Simulation-Realtime 切换都**修不好**渲染。报告需要绿色拓扑图时，用 PIL 把截图里的
 红线像素改成绿（前提：ping 已验证全通，原图另存）。

### 新路由器首次开 CLI 停在初始配置对话框
- **症状**：`Would you like to enter the initial configuration dialog? [yes/no]:` ——
  之后粘贴的每一行都被当成回答吃掉，配置全部落空。
- **解法**：开 CLI 后先贴 `no`，再贴一个空行（RETURN 进入提示符），然后才是正常配置。

### 控制台会话模式会漂移——贴命令前先 RETURN + enable
- **症状**：之前某次 `exit`/异常让会话停在用户模式 R1> 或登出（"con0 is now available /
  Press RETURN"）；此时贴 `ip route` 等命令全部 "% Invalid input detected"。
- **解法**：每次打开 CLI 贴命令前：先贴空行（RETURN）→ `enable` → 需要时 `configure
  terminal`。不要假设上一次会话的模式还在。

### 控制台快速连续粘贴会丢字符
- **症状**：`ip route 0.0.0.0 0.0.0.0 10.0.13.2 120` 贴完表里显示 `[1/0]`（120 丢了），
  相邻行整个没生效——粘贴间隔太短（<0.6s）时 PT 控制台偶发丢尾巴。
- **解法**：关键路由/配置命令用慢贴（每行 sleep ≥1.5s）；贴完 `show run` |
  `show ip route` 回读验证，不要信粘贴回显。

### 画布视图平移状态会存进 .pkt
- **症状**：重开文件后画布一片白（设备都在，视图被平移到几千像素外），状态栏 x:y 显示
  远超屏幕的坐标；Zoom Reset 修的是缩放不是平移。
- **解法**：View → Zoom → Zoom Out 两三下把设备找回来，再 Zoom In 回来；或直接接受
  缩小视图。平移在文件里持久存在，删不了就绕。

### 删线：点线 + DEL 删不掉，用 X 删除工具 + 像素扫描定位
- **症状**：删某条线时点击总是不中（线只有 ~3px 宽），DEL 按了没反应。
- **解法**：用 PIL 扫描截图找线的精确像素行（沿已知 x 列找暗/红像素簇）→ 点工具栏
  **X 删除工具 (81,94)** → 精确点击线的中心 → esc 收起。点线 + DEL 键的方式不可靠。

### 模块拖拽会顶掉占用槽位上的模块（连带删线）
- **症状**：往背板拖新模块时坐标偏到占用槽 → 旧模块被替换，接口名变（如 Serial2/0 消失、
  多出 FastEthernet0/0），挂在旧接口上的线断。
- **解法**：拖之前放大背板图确认目标槽是空的；拖完 dump 端口菜单核对接口清单；
  Power 开关 (Router-PT: 1235,316 / 1841: 1131,315)。

### 报告截图：PT 串口/画布的坑之外
- IP Configuration 面板坐标**每个会话都漂**（本次会话：IPv4 (1070,354)、掩码 (1070,379)、
  网关 (1070,406)、DNS 清理 (1070,432)）——第一台 PC 贴完必须截图核对。
- PC 的 Command Prompt 历史跨打开保留：批量 ping 分批截图时，每批完整出现在窗口尾部
  即可（2 个 ping/批），避免截到半截输出。

## Lab4 v2 专项（2911 菱形环，2026-10-15）
- **PT 8.2 路由面板没有 2811**（到 2620XM 就没了）。子面板用两端小箭头滚动（右 (705,1004)/左 (218,1004)，一下一项）；拖滑块会冲过头进空白区。Miscellaneous 快捷行里有 2811/2911 图标（x≈450/489）。
- **2911+HWIC-2T 的串口名跟物理槽走**：本次拖进 slot 3 → `Serial0/3/0, Serial0/3/1`。别假设 0/0/x —— 以端口菜单（UIA）或 Config 树为准。
- **2911 端口菜单里 Gi 插头不是黄色** → ptlib 的 fe_anchor 扫不到，一律用 `wire_uia(icon, A, "GigabitEthernet0/0", B, "FastEthernet0/1")` 按名字点。被占端口不出现在菜单 → menu_click raise，重试后仍失败说明端口选错了。
- **2911 电源开关在前面板左下**（绿色拨杆）：Physical → Zoom In → 视图竖滚动条(x=1278)拉到底 → 点 (947,578) 关电 → 拉回顶部拖 HWIC-2T (674,288)→HWIC 槽 (855,325) → 拉到底开电 → 关对话框等 ~45s 启动。
- **对话框残留会把下一次脚本的画布点击吞掉**（坐标落在旧对话框上）→ 整套配置粘进错误设备。预防：每个脚本开头先点 dlg.close + esc。修复被污染路由器：`write erase` 后直接原地重贴正确配置 + copy run start；别跟 `reload` 的 `[confirm]` 纠缠（粘贴的 "no" 会被它当否定取消 reload）。
- **PT 的 IOS 没有 `terminal length 0`**；`--More--` 下回车只翻一行，且 More 挂着时粘贴的命令前几个字符会被吃掉（后续命令 % Invalid input）。输出超屏后尾部行（S* 行）不可靠 —— 要看 S* 用短命令 **`show ip route static`**（一屏放下 S 主机路由 + S* 默认）。
- 每次驱动脚本之间控制台模式会漂（user-exec 存活到下一脚本）：粘贴配置前先 空行 → enable → configure terminal。

## Lab5 v2 仿真模式专项（2026-10-20，最贵的一批——一整晚耗在"拍不到面板"上）

### 仿真事件缓冲区 ~48 条硬上限；被过滤的协议照样占名额
- **症状**：Capture/Forward 按几下就弹 "Buffer Full"；过滤器只留 HTTP+TCP 也没用。
- **原因**：缓冲上限 ~48 条事件；**被过滤器隐藏的事件（OSPF hello、STP、DNS…）仍计入缓冲**，
  只是列表里不显示。挂机让仿真跑几百秒 = OSPF hello 就能把缓冲塞满，之后每个新事件都被拒。
- **解法**：抓包前 Reset Simulation（唯一能清缓冲+时钟的按钮）；步进全程手动，
  会话结束（列表停止增长）就停手，绝不"多按几下看看"。

### Clear Event List ≠ Reset：只清列表不清时钟
- **症状**：点了 Clear，步进一两下又弹 Buffer Full。
- **原因**：Clear 只清显示列表，仿真时钟继续走，隐形事件立刻再填满。
- **解法**：要干净缓冲一律 Reset Simulation。Reset 前先关设备对话框（见下条）。

### DNS 是会话里最大的隐形消耗——用 IP 直访绕开
- **症状**：整个 HTTP 会话（~45 事件）压不进 48 条缓冲，尾部（HTTP 应答到达 PC）被拒。
- **原因**：DNS 请求+应答一来一回 ~12 条隐形事件占名额。
- **解法**：浏览器直接输 `http://202.118.100.25`（Web 服务器 IP）跳过 DNS——
  整个 TCP+HTTP 会话 ~40 条全部入缓冲，包括应答尾部。网关 ARP 只占 1-2 条，可忽略。

### Buffer Full 弹窗的检测与两种点法
- **症状**：弹窗反复出现且"自动消失"（脚本守护在点），人看到的是一闪而过。
- **解法**：检测**蓝色 i 信息图标**（像素区 795,488±15，蓝通道>150 且红<110；标题条/按钮区
  的暗像素检测会被画布虚线链路误判成弹窗——实付：40 次假"弹窗"）。两种处理：
  **Clear Event List (963,559)** = 清空列表重来；**View Previous Events (1080,559)** = 保留已捕获
  行继续（抓包中段弹窗用这个）。弹窗一开就吃掉所有点击，包括行点击。

### PDU 面板只显示"被选中行"；不随步进更新；点已选行=关闭
- **症状**：连按 40 次 Capture/Forward，面板内容纹丝不动；或面板莫名消失。
- **原因**：面板绑定的是**列表选中行**，不是"当前事件"；再点同一行 = toggle 关闭。
- **解法**：步进后必须**单击对应事件行**才开面板；对同一行永远只点一次；
  行内容核验用标题条截图（At Device/Source/Destination 两行）。

### 渲染延迟 ~1s：点了立刻截 = 空面板/旧内容（本次最大单一代价）
- **症状**：几十张截图全是空面板或上一个事件的内容。
- **原因**：Qt 面板点击后渲染要 ~1s，标签切换同理；脚本 0.3-0.5s 就截。
- **解法**：点行后 sleep ≥1.2s 再截；切标签**点两次、间隔 0.8s**；扫描模式 1.2s/行。
- **推广**：任何 Qt/自绘界面"点击后立即取证"都可能拿到旧帧（呼应公共坑 #22）。

### Details 标签行在 y≈295，不是 266
- **症状**：点 (836,266) 切不过去（三标签面板偶尔蒙对）。
- **原因**：266 是标题栏/标签上沿；标签文字本体在 y≈283-310。
- **解法**：标签点击用 (836,295)（Inbound）/(982,295)（Outbound），点两次隔 0.8s；
  两标签面板（纯出站事件）Outbound 也在 836 槽位。

### 纯 ACK 事件行：PT 只渲染 L2 帧，首部表拍不出来
- **症状**：第三次握手的 ACK 行（PC-A 与 SW-A）OSI 层 L3/L4 空、Details 无表，标签点不动。
- **原因**：PT 对 bare-ACK 事件只渲染到以太网帧层（SYN/SYN+ACK/GET/响应都正常）。
- **解法**：报告 ACK 槽用**出站事件面板**（At Device: PC-A, Fa0 sends out）+ 分析文字
  引用 SYN/SYN+ACK 里的 SEQ/ACK 递进关系。不要试图"找到正确的行"——不存在。

### 事件列表交互：滚轮无效、方向键即失焦、轨道拖拽=翻页
- **症状**：wheel 不滚；点行后按 ↓ 一次就停（焦点跳到面板）；拖滑块冲过头。
- **解法**：翻页用**滚动条轨道拖拽**（x=1907，从 y≈350 拖到 215=向上翻页、拖到 660=向下），
  拖完截图核对；行定位放弃"算坐标"，用**锚点法**：先点一个内容已知的行（如 0.017 SRV3），
  紧接着点目标行——目标行必被选中且面板打开（两次都是"切到新行"，无 toggle）。

### 设备对话框开着时 Simulation Panel 整体上移 ~58px
- **症状**：按记忆坐标点 Reset (1687,723) 落空，缓冲永远清不掉。
- **原因**：PC/Server 对话框打开时面板下部布局收拢，Reset 从 y≈723 移到 y≈665。
- **解法**：点面板按钮（Reset/Play/Forward）前**先关设备对话框**；或每次截图重测按钮位置。

### 步进节奏与"过站"
- **解法**：Forward (1820,779) 每 0.65-0.9s 一次；事件列表底部行停止增长 = 会话结束 = 停手。
  会话结束后再多按，每次都会跳进 OSPF 领地（+10s 仿真时间/次）并吃缓冲名额。

## Lab5 Dynamic Routing 专项（2911×5 环形+中心辐射,2026-10-21）

### PT 不认手工 `ip ospf cost`——改 `bandwidth` 才生效
- 症状：`ip ospf cost 500` 配置回显正常，但 `show ip route ospf` 度量值不变（仍 [110/65]），选路不变。
- 解法：改接口 `bandwidth 64`（cost=10^8/64000≈1562），SPF 立即重算，路由切到预期绕行路径。报告里注明"手工 cost 在 PT 中不生效"。

### PT 多区域 OSPF 不显示 O IA 标记
- 症状：区域划分命令全部生效（network ... area 1-4），但路由表里区域间路由仍显示 `O` 而非 `O IA`。
- 解法：不追标记；以配置回显 + 全网 ping/tracert 作为多区域生效证据，报告注明 PT 简化实现的显示差异。

### reload 的两道问答：先答 "no"（Save?），空行只对 [confirm] 有效
- 症状：write erase 后 `reload`，粘贴空行卡在 "System configuration has been modified. Save? [yes/no]:"，再贴空行报 "Please answer 'yes' or 'no'"，reload 始终没执行。
- 解法：`P("no")`（Save? 不保存）→ `P("")`（Proceed with reload? [confirm]）。且 PT 的 reload 可能被取消（提示符直接回来）——与 Lab4 结论一致：**别跟 reload 纠缠，write erase 后原地重贴配置**。

### fshot()/repaint() 默认窗口匹配子串 'lab5.pkt'，文件名不含它就 raise
- 症状：`pt.fshot("x")` 报 "window 'lab5.pkt' not found"，即使 PT 明明开着（如文件叫 lab5_rip.pkt / lab5_dynamic_routing.pkt）。
- 解法：fshot 的默认 title_sub 是写死的 'lab5.pkt'；先 `pt.repaint("Packet Tracer")` 也躲不过 fshot 内部再次调用。兜底：直接 `pt.py send shot`（不重绘的普通截图），或改 ptlib 的默认子串。
- 附带：残帧显示器会给出**几天前的旧桌面**（带旧日期任务栏），先 `send shot` 拉回看真实状态再动作。

### 串口对端没配 IP 时"R5 全配完但 show ip ospf neighbor 空"的假故障
- 症状：中心路由器接口 up 配置齐全，但 neighbor 表空、对端路由缺失；`show ip int brief` 显示串口 down/down。
- 原因：辐射链路的对端（四角路由器 S0/3/1）还没配 IP/no shut——线是连了但两端只有一端活。
- 解法：逐台补对端接口配置后立即 FULL。排障顺序：链路两端 brief → neighbor → route。

### Lab5 v2 专项追加（2026-10-21 晚）

### passive-interface default 会"动态"覆盖后创建的接口
- 症状：路由器先配 `passive-interface default` + no passive 两个串口；之后新增第三个串口（S0/3/1）并宣告进 OSPF，
  该口被默认置为被动 → 邻居起不来（对端 show ip ospf neighbor 空），但网段仍会通过环网泛洪（ping 通、有路由）。
- 解法：新增接口后逐台补 `no passive-interface serial0/3/1`。排障链路：ping 对端通 + 邻居空 → 查 passive。

### PT 设备改名重名会静默失败
- 症状：批量改名 PC0→PC1、PC1→PC2…（递增错位）时，rename 全部无效，画布保持旧名；路由器/交换机改名（无重名）正常。
- 原因：目标名与现有设备重名，PT 拒绝但不报错。
- 解法：逆序改名（先改最大号），或先改成临时名。ptlib.rename_device 应考虑加此提示。

### RIP 的 network 写 C 类主网 192.168.0.0 不匹配任何子网
- 症状：链路 ping 全通、RIP 进程在、但 show ip protocols 的 Routing Information Sources 为空、路由表只有直连。

- 解法：C 类地址空间必须逐 /24 主网宣告。教学价值高，适合写进报告排障实录。

### PT 的 `ip ospf cost` 不生效（复现第二次）
