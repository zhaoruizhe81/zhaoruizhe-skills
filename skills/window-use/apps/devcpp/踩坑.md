# Dev-C++ 5.11 私有坑（2026-11-02 实验一代做实战）

## D1 硬杀后重启弹「首次配置向导」，配置疑似只在正常退出时持久化
- **症状**：`taskkill /F /IM devcpp.exe` 后再启动，弹 "Dev-C++ first time configuration"（此前明明已配置成中文界面并正常使用过）。
- **代价**：实付一轮排障 + 3 步向导。
- **解法**：向导三页坐标（1920×1080，对话框右上区）：语言列表点「简体中文 (Chinese)」(985,463) → Next (1083,687) → 主题页 Next (1083,687) → 完成页 OK (1083,687)。完成后配置恢复中文。
- **预防**：能不杀就不杀——单实例走完全程，后续文件用 Ctrl+O 打开。

## D2 F9 编译"没反应"：焦点残留在菜单栏
- **症状**：菜单点击后 esc 关闭菜单，再按 F9 无任何反应、无报错、目录里无 exe 产出（平行通道 `ls` 验证）。
- **原因**：esc 后菜单栏仍持有键盘焦点，功能键被吞。
- **解法**：按键前先 `click(700,400)` 点编辑区拿焦点。序列固定：raise → click 编辑区 → f9。
- **验证**：编译成功看底部「编译日志」面板（错误: 0 警告: 0）或 ssh `ls` 看 exe mtime。

## D3 编译日志面板默认折叠
- **症状**：底部只有标签条（编译器/资源/编译日志/调试/搜索结果），无日志内容。
- **解法**：点「编译日志」标签 (188,994) 展开。

## D4 快捷键实测：F9=编译 F10=运行 F11=编译运行
- 点「运行[R]」菜单 (287,31) 截图核对过菜单项与快捷键（5.11 中文版，TDM-GCC 4.9.2）。不确定快捷键时先开菜单截一张，看完 esc。

## D5 Ctrl+F4 关标签页无效；Ctrl+O 打开已打开的文件=切回旧缓冲区不重载
- **症状**：磁盘上改了 .c 文件，编辑器里 Ctrl+F4 无反应；Ctrl+O 重开同一文件只切回**旧内容**标签（状态栏"长度"还是旧值）。
- **代价**：实付一轮（重开失败 + 编译出旧版 exe 前被发现）。
- **解法（改源文件内容进编辑器的唯一可靠姿势）**：click 编辑区 → ^a 全选 → `set_clip(新源码)` → ^v 覆盖粘贴 → ^s 保存。粘贴 Unicode 剪贴板会按 ANSI/GBK 落盘，中文注释无损。
- **副作用**：保存后再获得焦点时可能弹「文件已经改变. 重新从硬盘读取?」Confirm（Yes (912,578)）——磁盘是最新版，点 Yes 重载。

## D6 运行期间主窗口标题插 [Executing]，title 匹配失败
- **症状**：`raise_topmost('card.c - Dev-C++')` 报 no window——运行中标题变成 `card.c - [Executing] - Dev-C++ 5.11`。
- **解法**：运行期间匹配 `'card.exe'`（ConsolePauser 控制台标题）；匹配主窗口用不含文件名的 `'Dev-C++'` 或把 [Executing] 算进去。
- **连带坑**：控制台忘发键关闭 → 下一轮 raise 主窗口失败（标题还挂着 [Executing]）。脚本收尾必须 `press('enter')` 关控制台。

## D7 find_window 按 '.*xxx\.c.*' 匹配报 ElementAmbiguous（2 个元素）
- **原因**：win32 后端下 Dev-C++ 主窗口（标题含完整路径+文件名）与 MDI 子窗口（标题只有文件名）都匹配。
- **解法**：主窗口用 `'xxx\\.c - Dev-C\\+\\+'` 全模式；只定位编辑器子窗口时才用短模式。

## D8 GBK 源文件是中文正常显示的前提
- Mac 侧生成：UTF-8 写 → `text.replace('\n','\r\n').encode('gbk')` → SFTP push。Dev-C++ 5.11 默认 ANSI(GBK)，TDM-GCC 对 GBK 中文注释/字符串编译无误，GBK 控制台（cp936）显示正常。UTF-8 源文件会注释乱码/字符串乱码。

## D9 printf 中文卡片对齐：字节宽=显示列宽，但必须逐行数
- GBK 下 1 汉字=2 字节=2 列，printf 的 %-Ns 按字节补齐恰好等于显示列对齐。
- **症状**：右边框参差（实付 3 轮：先改错方向，又发现系统性 off-by-one）。
- **根因**：混排行的空格是手数进字面量的，容易漏"边框前那个空格"。
- **解法**：统一行结构 `|` + 空格 + **20 格内容** + 空格 + `|`（边框 22 划=总 24 列），每行按"标签(6格)+值+补格=20"算完再写字面量；验证以渲染截图像素为准。

## D10 控制台输入
- 纯数字：`typeln('15 4')` 直接打（IME 在英态时数字安全；不确定先 press shift 切英态）。
- 中文（如 `张三 19 M 数字媒体技术 数媒103班 编程`）：`set_clip(...)` → 控制台 `hotkey ctrl+v`（Win11 conhost 支持）→ enter。一整行多数据粘贴一次即可，`scanf("%s %d %c"...)` 会按空白逐项消费。
- 运行结束 ConsolePauser 停在「请按任意键继续」，`press('enter')` 关窗。截图要在关窗前拍；控制台窗口太小放不下全部输出时，可 find_window('xxx.exe') 后 `w.maximize()` 再拍。

## D11 桥脚本输出回传
- script 注入脚本里 `print()` 不可见（pythonw 无控制台），要回传数据用 `log()`（进 gui.log，`pt.py log` 拉回）或写文件后 pull。
- `pt.py step` 自动拉与脚本同名的最后一张 shot；脚本里 shot 名不同就手动 `pt.py pull <name>`。
