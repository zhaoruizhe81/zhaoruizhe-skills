# Excel 自动化踩坑（windowpc / Office 365 实测）

## ffmpeg 强杀 = ts 0 字节（-flush_packets 缺失）
- **症状**：gdigrab 录制后 taskkill /F 或 p.terminate()，ts 文件存在但 0 字节；同参数加 `-t N` 自然退出就有数据。
- **原因**：ffmpeg 输出缓冲未刷盘，强杀把缓冲全丢。
- **解法**：命令行加 `-flush_packets 1`（逐包写盘），terminate/taskkill 均安全；或 stdin 写 `q` 优雅退出（备选）。实测 2026-10-17。

## Game Bar 录屏不可用
- **症状**：pyautogui 发 Win+Alt+R 无反应，Videos\Captures 不生成文件。
- **原因**：该 PC 注册表无 `HKCU\Software\Microsoft\GameBar\AppCaptureEnabled`，Game Bar 被精简。
- **解法**：直接用 ffmpeg gdigrab（PC 上已有 winget 装的 ffmpeg 8.1.1），更可控。

## taskkill /F 杀 Excel → 文档恢复面板
- **症状**：强杀后重开文件，左侧出现"文档恢复"窗格，录屏画面被污染。
- **解法**：pywinauto `win.close()` + 保存对话框点「不保存」（descendants 找 Button，兜底 Alt+N）。

## pt.py send 传 crop 参数不兼容
- **症状**：`pt.py send crop f1 x1 y1 x2 y2` 报 `crop() takes 5 positional arguments but 7 were given`。
- **解法**：crop 写进脚本内执行（script 注入环境里 crop(name,x1,y1,x2,y2) 正常）。

## 勾选复选框后立即全屏截图像"没生效"
- **症状**：点字段复选框后 sleep 3 截全屏，看似未勾选。
- **原因**：窗格重绘慢 + 全屏图太小看不清勾选标记。
- **解法**：用 crop 放大字段窗格区域再判；或加大 sleep。别急着重试第二次点击（会把已勾的又取消）。

## 样式库弹出层截图坐标缩放
- **症状**：下拉弹出的完整样式库截图回来是 1440×810，按图上坐标点击脱靶。
- **原因**：截图回传被缩放。
- **解法**：换算 ×4/3；或直接 crop 目标区域（crop 返回 2x 原尺寸），一律以 crop 结果定坐标。

## ffmpeg 字幕滤镜三连坑（Mac 精简版 / PC full build 都踩了）
- **症状1**：Mac homebrew ffmpeg 报 `No such filter: 'ass'/'subtitles'`——该构建无 libass，别纠缠，换 full build 的机器烧。
- **症状2**：报 `No option name near 'sub.srt:...'`——新版 ffmpeg 滤镜不接受位置参数，必须 `subtitles=filename=sub.srt:...` 显式键名。
- **症状3**：报 `Unable to open sub.srt`——计划任务进程 CWD 不在 ptauto，相对路径失效；用转义绝对路径 `filename='C\:/Users/master/ptauto/sub.srt'`。
- force_style 值含逗号必须整体单引号包裹；含空格的字体名（PingFang SC）会炸解析，用无空格字体（STHeiti / Microsoft YaHei）。
- 烧录脚本走 subprocess list argv（不进 shell），单引号原样到达 libavfilter，无 Git Bash 引号地狱。

# Excel 2024/365 新版 UI（2026-10-25/26 经济统计实训实战）

## 登录墙"登录以验证你的订阅"是模态框，Esc 可关
- **症状**：打开 xlsx 弹"登录以验证你的订阅"模态框；此时主窗口 `is_enabled()` 为 False，按标题 find_window 等使能全部超时返回 None。
- **解法**：先 `pyautogui.press("esc")` 关弹窗再找窗口（实测 Esc 有效）；别对主窗口 set_focus（模态期间 NoneType 报错）。

## "分析数据"绿色提示栏遮挡表头
- **症状**：新工作簿打开后左上角绿色提示栏（启动分析数据/稍后使用）盖住 A1 标题区，每张表都在。
- **解法**：点"稍后使用"（实测 1920×1080 下 ≈(453,246)）后本会话不再出现；截图前先清它。

## Ctrl+PgDn 切工作表不稳定，点标签最稳
- **症状**：`ctrl+pagedown` 连续多次切表，中间会静默失效（截图停在原表），脚本序列错位。
- **解法**：改直接点底部工作表标签（固定 y≈995@1080p，x 按标签宽累计）；一步到位不依赖键盘焦点。

## Ctrl+` 公式视图切换可靠——但有 IME 前提（2026-10-31 补）
- `ctrl+反引号` 整表切换 显示公式/显示值，截图"过程证据"两连拍的标准姿势；再按一次还原。注意公式视图下列宽会变宽，先切值视图截结果、再切公式视图截过程。
- **前提：IME 必须是英文模式**。微软拼音"中"状态下 Ctrl+` 被IME吞掉（静默无效果，2026-10-31 实付一轮）；任务栏显示"中"时先 `pyautogui.press("shift")` 切英文（再 shot 任务栏确认"英"）。切换后一次通过。

## Ctrl+滚轮缩放 synthetic 输入无效，走状态栏"100%"开缩放对话框（2026-10-31 实付）
- `keyDown ctrl + scroll(-n)` 对本机 Excel 2024/365 缩放**无效果**（SendInput 滚轮带ctrl未被识别），别浪费时间调参数。
- **正解：点状态栏右侧"100%"标签(1893,1019) → 缩放对话框 → 点档位单选 → 确定**。
  坐标（1920×1080）：50%(900,519) 75%(900,494) 100%(900,470) 200%(900,445) 确定(967,637) 取消(1015,637)。缩放对话框按sheet各自记忆，切表后要分别设置。

## 脚本里开过的模态对话框，收尾必须关掉（2026-10-31 实付）
- 缩放对话框开着不关 → 下一轮脚本前几个点击全被模态吞掉（点击落空、shot拍到旧状态，公#11e 的对话框变体）。
- 铁律补充：**凡是本脚本打开的对话框，脚本最后一步必须关闭它**（确定/取消/esc 均可），并 shot 确认无残留。

## 切工作表标签的点击会延迟生效，切完必须验证（2026-10-31 实付两次）
- 点击底部标签后 sleep 2 截图，可能拍到**旧表**（点击延迟数秒才生效），后续所有"在该表上"的动作实际落在别的表上，连锁错位。
- 解法：切表后 sleep 5 + shot 验证当前表（看左上名称框/活动标签高亮），确认后才继续动作。

## 保存提示按钮位置每次都不同，crop 实测再点
- **症状**：Alt+F4 弹"是否保存对xxx的更改?"，"不保存"先后出现在 (1040,553)、(1000,567)、(958,574)——布局随对话框来源（工作簿/语法/数据集）变化，老坐标必脱靶。
- **解法**：shot → crop 放大按钮区实测坐标 → 点击 → 再 shot 验证。强杀 Excel 前确认磁盘文件无损即可无脑 taskkill。

## 强杀 Excel 后清两处恢复缓存，防"文档恢复"面板
- `taskkill /F /IM EXCEL.EXE` 后删 `%AppData%\Roaming\Microsoft\Excel\*` 和 `%AppData%\Roaming\Microsoft\UnsavedFiles\*`，下次启动不弹文档恢复（比 2026-10-17 条目的 win.close 方案更彻底）。

## openpyxl 写的公式无缓存值，真 Excel 打开自动重算（正面经验）
- openpyxl 只写公式字符串不含结果，Excel 打开时自动计算并显示——无需 LibreOffice recalc，直接在真 Excel 里截图验证即可；公式视图截图就是"过程证据"。
