# Huawei eNSP 私有坑（公共坑见根目录 踩坑清单.md，远程坑见 remote/远程坑.md）

环境基准：eNSP V100R003C00SPC100（eNSP_Client.exe 1.2.00.510，topo 版本串 1.3.00.100），
win135 笔记本，1920×1080。2026-11-04 企业园区网 VLAN 考试实战，排障 2h+ 的实付。
每条都是 症状 → 原因 → 解法。

## N1. 手写 .topo 加载时【静默丢弃】所有 PC↔交换机连线（最贵的一课，2 小时）

- **症状**：脚本生成的 .topo，设备（PC/交换机）全部正常加载，但 PC→交换机的线打开就没了；
  switch↔switch 的 trunk 线却好好的。某些变体里 PC 线"看着渲染出来了"实为死线——
  `display interface brief` 里交换机所有 Ethernet 口 `down down`，只有 trunk 口 `up up`。
  更坑的是用 eNSP 重新保存后丢的线**永久消失**（保存只写内部模型里真实存在的线）。
- **原因**：加载器要靠设备 slot 里的接口声明来绑定线的 srcIndex/tarIndex。
  交换机的 slot 声明了 `<interface .../>` 所以 trunk 能绑；**PC 的 slot 是空的（或没有 slot）**
  → index 0 无处可绑 → 整条线被静默丢弃。调 tarIndex/几何/缩进/ID 全是死路（testF~testM
  7 个变体全败），因为根因在 dev 条目不在 line 条目。
- **解法**：给每台 `model="PC"` 的 dev 注入（抄官方示例 Campus_Network.topo 的写法）：
  ```xml
  <slot number="slot17" isMainBoard="1">
      <interface sztype="Ethernet" interfacename="GE" count="1" />
  </slot>
  ```
  工具已固化：`apps/huawei-ensp/fix_topo.py <in.topo> [out.topo]`（注入接口声明 + 统一 CRLF）。
- **验证 ground truth**：打开拓扑 → eNSP 里 保存 → 数新文件里 `<line ` 条数（保存回写 =
  内部模型真相）。渲染截图不算数（死线也渲染）。
- **教训**：遇到"加载丢数据"先找**官方同格式样例**逐字段 diff（本机就有：
  `C:\Program Files\Huawei\eNSP\examples\**\*.topo`），别瞎枚举变体。

## N2. .topo 文件格式细节（手写时照抄 eNSP 亲保存文件）

- 行尾必须 **CRLF**（eNSP 保存即 CRLF；LF 的手写文件行为未定义，别赌）。
- XML 声明 `encoding="UNICODE"` 但**实际字节 ASCII/UTF-8 即可**（官方示例就是 ASCII，
  eNSP 按 BOM 嗅探，不认 declaration）。
- `<topo version="...">` 用本机 eNSP 保存出来的版本串（此处 1.3.00.100）；
  官方示例的 1.2.00.300 也能加载，不敏感。
- 权威格式来源优先级：① 本机 eNSP 保存的 topo（testM）→ ② examples 官方示例
  → ③ 猜。三个都在比对手写才靠谱。
- dev 属性 `poe="0"` `system_mac` 等：新版本 eNSP 保存会带；缺了也能加载（官方老示例没有）。
  **但 slot 接口声明缺了必炸（N1）**。

## N3. 打开拓扑的可靠方式 = 杀进程 + 文件关联启动（不走 GUI 打开对话框）

- **配方**：
  ```python
  subprocess.call('taskkill /F /IM eNSP_Client.exe', shell=True)
  subprocess.call('taskkill /F /IM eNSP_Switch.exe', shell=True)      # 不杀会占着 telnet 20xx 端口
  subprocess.call('taskkill /F /IM eNSP_VBoxServer.exe', shell=True)
  subprocess.Popen('cmd /c start "" "D:\\path\\xxx.topo"', shell=True)  # assoc: .topo=topofile
  ```
- 好处：无保存提示、无打开对话框坐标、无半加载状态；拓扑窗口按 topo 里存的几何自动还原。
- 三个进程都要杀（N7）；杀完 sleep 2 再启动。

## N4. eNSP 冷启动加载拓扑要 2~5 分钟，期间画布是空白"新建拓扑"

- **症状**：`start xxx.topo` 后 35s 截图 → 标题"新建拓扑"空白画布，以为启动失败；
  在此期间摆设备/点击全是无用功（还留下 7 台幽灵设备污染判断）。
- **真话**：拓扑在后台慢慢加载，加载完成后画布整体切成目标拓扑，窗口按 topo 几何还原
  （通常非最大化）。
- **解法**：启动后**只轮询不交互**——截图看标题栏中央文字变成 topo 名（如"企业园区网络设计"）
  才算加载完；或数画布设备（状态栏"总数: N"）。冷启动轮询预算给足 5 分钟。
- **教训**：截图里的"空白新建拓扑"≠启动失败；截图与用户口头描述不一致时，先怀疑
  各自看到的是**不同加载阶段**（以及 N10 的多会话），别急着推翻自己的操作。

## N5. 连线的 GUI 位置：左侧面板"设备连线"类别；拖拽=移动设备

- 工具栏**没有**连线工具；右键设备菜单**没有**连线项。别在这两处浪费时间（实付）。
- 正路：左侧设备面板切到 **设备连线** 类别 → 点线缆类型图标（自动选择/Copper/Serial…）
  → 点源设备 →（Copper 弹接口菜单选口；Auto 不弹）→ 点目标设备 →（弹接口菜单）→ 线成。
- **拖拽设备 = 移动设备**，不是连线；失败的反向拖拽会把设备拖得叠罗汉（PC1 曾被拖进
  交换机里两次）。
- 工具栏有"删除所有连线"按钮，清线重连用。
- **注意**：本实战最终走 XML 直改（N1 fix_topo.py），GUI 连线在远程桥下未验证成功过
  （Qt 菜单点击同 Packet Tracer 的坑，见 apps/cisco-pt/踩坑.md——一条线一次触发、
  moveTo 慢点击、菜单消失≠选中）。能改 XML 就别 GUI 连线。

## N6. 进程与窗口模型（杀错/找错全白干）

- 主进程 `eNSP_Client.exe`；**OS 窗口标题就是 'eNSP_Client'，不含拓扑名**（拓扑名是
  窗口内自绘标题栏文字，EnumWindows 看不见）→ focus 用 "eNSP" 子串匹配。
- 设备进程：每台 LSW 一个 `eNSP_Switch.exe`（VBoxServer\Devices\Lsw\<型号>\ 下），
  `eNSP_VBoxServer.exe` 管 AR 路由器的 VBox。杀 eNSP 必须连它们一起杀，
  否则残留实例占着 telnet 2000/2001 端口，新拓扑设备起不来或串台。
- eNSP 以管理员运行 → 非提权桥的点击被 UIPI 吞 → 必须用 /rl HIGHEST 的桥任务
  （win135 上是 EnspBridgeE，见 remote/远程坑.md §10）。

## N7. 交换机 CLI 有平行通道：Telnet 127.0.0.1:<com_port>（比 GUI 快十倍）

- topo 里 dev 的 `com_port="2000"` = 启动后 `telnet 127.0.0.1 2000` 直达 VRP 控制台
  （2001=第二台）。发 `display interface brief`、`display vlan`、`display ip routing-table`
  收回显，全程不碰 GUI。
- Python socket 实现（含 telnet IAC 协商字节剥离）见笔记本
  `D:\20zy\eNSP安装包\ensp_telnet.py`，照抄即可。
- **限制**：只有交换机/路由器有；PC（simpc）没有 telnet——PC 的 ping 测试仍走 GUI
  （右键 PC → 设置 → 命令行 页签，见 N13）。
- `screen-length 0 temporary` 在 console 口报 "The type of the included user interface
  must be VTY"——**忽略即可**，长输出会带 `---- More ----` 但所需内容通常已在其中；
  要彻底免分页就配 VTY 或忽略。

## N8. 设备配置自动加载：<topo目录>/<设备ID>/vrpcfg.cfg

- 设备启动时 eNSP 自动套用同目录下以其 ID 命名的文件夹里的 vrpcfg.cfg
  （sysname 生效即证明）。改配置 = 直接改该 cfg 文件再启动设备，或 GUI 控制台敲。
- 两台交换机的考试配置（VLAN/access/trunk/Vlanif 网关）就放在拓扑旁边
  的 B1000*-…/ 文件夹里，随拓扑走。
- **取证别看拓扑旁的参考 cfg**（如 S3700-Jieru-SW.cfg——它写的 E0/0/24 trunk 与实际
  生效的 GE0/0/1 trunk 不一致）：设备真正自动加载的是 `B1000*-…/vrpcfg.cfg`，
  写报告/核对配置一律拉这个文件或直接 `display current-configuration`。

## N9. 设备状态颜色与启动

- 图标蓝=未启动，橙=启动中（每台 10~30s），跑起来后端口两端绿点=链路 up。
- 启动方式：右键设备 → 启动；或框选全部（空白处橡皮筋拖拽，起点终点必须在空白画布上，
  落在设备上就变成拖动设备了）→ 工具栏 ▶ 启动设备（停止=旁边红 ■）。
- 启动后给 60~90s 再做连通性测试（STP 收敛 + VRP 起来）。

## N10. "我截图的和你屏幕上不一样"排查链（2026-11-04 实付 40 分钟）

按顺序查，每步都有硬数据：
1. `tasklist /V | grep -i ensp`（**加 MSYS_NO_PATHCONV=1**，/V 会被 Git Bash 路径转换吃掉）
   看 Session 列——Console 还是 RDP。两台机器/两个会话是最常见根因。
2. 桥里跑 `win32api.GetSystemMetrics(0/1)` 拿**交互会话**真实分辨率。SSH 会话里
   `Screen.AllScreens` 报 1024×768 是 session-0 假象，别信。
3. EnumWindows 列全部可见窗口——eNSP 窗口 OS 标题恒为 'eNSP_Client'（N6），
   多实例时 focus 会抓错（focus 循环逐个 SetForegroundWindow，最后落在 Z 序最底的那个
   ——应改为只激活第一个/匹配的那个）。
4. `EnumDisplayMonitors` 在部分 pywin32 版本不存在（AttributeError），多显示器判断
   用 GetSystemMetrics(76..79) 虚拟屏参数代替。
5. **用户人在笔记本前时**：画布内容"无中生有"（多了 4 台交换机）、菜单被点开又关、
   任务栏时钟跳变 = 用户在实时操作。先停下来问，别跟用户抢鼠标——远程点击和
   本地手互为噪声，双方都做不成事。
6. 驱动截图左上角有时间戳水印，但它和任务栏时钟可能差 2.5h（机器 NTP 校正过）——
   对齐新旧截图别用时间戳，用 gui.log 的 DONE 顺序。

## N13. 双击设备【打不开】配置窗口——开窗正路是右键菜单（2026-11-04 测试阶段实测）

- **症状**：对 PC 图标做标准间隔的合成双击（down/up + ~90ms + down/up）连试 3 次，
  设备只是被选中（变橙），配置窗口从不弹出；交换机同理没有双击开控制台。
- **正路（实测 3 PC + 2 SW 全成）**：
  - PC 配置窗：右键设备 → **设置**
  - 交换机控制台：右键设备 → **CLI**
  - PC 菜单项：启动/停止/对齐到网格/删除/数据抓包▶/设置/播放
  - 交换机菜单项：启动/停止/导入设备配置(灰)/导出设备配置/对齐到网格/删除/数据抓包▶/CLI/设置
- **菜单位置可盲点**：菜单左上角 ≈ 点击点 +(8,6)，"设置" ≈ 点击点 **+(40,+178)**，
  "CLI" ≈ **+(38,+240)**（同 y 点击时）。盲点后必须 find_win 兜底验证。
- **窗口动态定位配方**（比记坐标稳，多分辨率通用）：开窗后 EnumWindows 按**设备名**
  找窗（OS 标题即设备名，如 "PC1-Xiaoshou"/"Hexin-SW"，取 GetWindowRect）：
  - "命令行"页签 = (L+180, T+63)
  - 控制台/命令行区给焦点 = (L+480, T+245)
  - 关闭 X = (R-30, T+16)
  找不到窗口就只截图不盲点（失败安全）。
- **PC 控制台批量粘贴可行**：一次触发里连贴 2~3 条 ping（每条间隔 12~16s 等回显）
  实测全成——"一条/次"铁律只针对 Qt 弹出菜单类动作（连线），控制台粘贴不受限。

## N14. eNSP V100R003C00 没有 PT 式模拟面板（2026-11-04 实验三实战）
- **症状**：找“模拟方式/Add Simple PDU”遍历 菜单(文件/编辑/视图/工具/考试)、整条工具栏、画布四角均无；链路上右键也无菜单（只有悬停 tooltip“删除连接”）。
- **解法**：观察报文用**设备右键 → 数据抓包 ▶ → 接口**（Wireshark 4.x 实时抓包，标题为 "Capturing from Standard input"，EnumWindows 按 "Capturing from" 子串找）+ 设备真实 ping。抓包窗口关闭用 taskkill /F Wireshark.exe dumpcap.exe（WM_CLOSE 会弹保存框）。
- **抓包实验配方**：每轮 = 清交换机 MAC 表(sys→undo mac-address all，user view 下该命令不存在) + PC0 arp -d → ping → 截 Wireshark → taskkill。display 过滤条在窗口 (L+440,T+106)。

## N15. 右键菜单项坐标：同 y 设备一致，y=640 向下开、y≥850 向上翻
- 菜单框 ≈ 点击点 x+8 起；文字项 x≈点击点+40。y=850 的设备菜单上翻，项序（PC，已启动）：停止+30/对齐+61/删除+91/数据抓包+121/设置+151/播放+182（相对点击 y-173 起，步距 ~31px）——**必须 rclick 后 shot 核对再点**（本战实付：盲点 666,801 点在菜单框外，白费 5 轮）。多设备选中态下菜单项会变，先点空白取消选择（否则误触“删除”弹确认框）。

## N16. PC 设置窗字段坐标与窗口层叠
- 窗口标题=设备名，首个弹出居中 (473,178,1449,844)，后续**层叠偏移**（第二个 566,278…）——每次 FindWindow+GetWindowRect 动态定位，字段：主机名(L+528,T+127)、IP(L+290,T+273)、掩码(L+290,T+317)、网关(L+290,T+361)、应用(L+884,T+616)、关闭X(R-30,T+16)。
- 点阵式 IP 控件可直接 paste_at 整串 "210.137.1.10"（自动分段），无需逐段输入。
- “主机名”≠设备名，改它不改变画布标签；**设备改名只能改 topo XML 的 name 属性**（两遍占位法防冲突，改后杀进程重开拓扑，PC 的 IP 配置存于 topo 不丢，路由器 VRP 配置会丢需重发）。
- eNSP 主窗被其他窗（如 Windows 系统设置，标题也叫“设置”）遮挡时 SetForegroundWindow 会拉错窗；别对主窗 SW_RESTORE（会变非最大化导致坐标全偏）。

## N17. VRP 命令速记（S3700/AR2220 telnet 127.0.0.1:200x）
- 清 MAC：`sys` → `undo mac-address all`（user view 无此命令）。
- 清 ARP：`reset arp dynamic`（user view；`undo arp <ip>`、`undo arp dynamic` 均不存在）。
- telnet 会话里 `save` 的 (y/n) 提示秒超时自动取消，y 发慢了报 Unrecognized——配置持久化改走重发配置脚本。
- eNSP PC 命令行支持 `arp -a`/`arp -d`/`ping`/`ipconfig`。

## N18. eNSP 设备 GUI 控制台 = 全会话镜像流，旧窗残留会拍出"假证据"（2026-11-04 换 IP 重拍实付）
- **症状**：Router0 GUI 控制台 display arp 拍出 40 分钟前的旧 IP 表项；排查发现 FindWindow("Router0") 找到的是**没关干净的旧控制台窗**（缓冲里还有旧会话回显），且 GUI 控制台会把 telnet 会话敲过的命令/输出一并镜像显示。
- **解法**：拍证据前先 EnumWindows 按**精确标题** WM_CLOSE 关掉该设备全部旧窗；重开窗口用"开启前 diff 出新 hwnd"验证是新窗（别只按标题 FindWindow，会命中旧窗）；crop 前确认缓冲里最新一条命令的输出完整可见（PC 控制台 crop 高度不够会截掉最后的空表输出，先敲的命令越少越好）。

## N19. 学号末三位以 0 开头时，IP 网段去掉前导 0
- 指导书"210.XXX.x.x（XXX=学号标识）"：XXX=051 这类前导 0 写法在 IP 里非法/歧义（VRP 拒绝），按惯例 **051→51**（210.51.1.0/24）。换学号重配时：路由器 `ip address` 直接覆盖原主 IP；PC 逐台重配（已有 per-PC 脚本 sed 210.137→210.51 即可）；**重拍顺序**：先跑连通性 ping（脏态），再清态出初始态证据，最后抓包（每轮抓包自带清态）。注意路由器预热 ping 会把它经过的交换机 MAC 表重新填上——**清交换机表必须在预热 ping 之后**。

## N20. 报告类交付：换 IP/换图后必须重跑生成脚本（docx 内嵌图不随源文件更新）
- 症状：替换了截图目录里的 PNG，但 docx 里仍是旧图（图片在生成时已嵌入 word/media/）。

## N21. step 末尾自动拉截图恒 DOWNLOAD-FAIL（拉图竞态）
- **症状**：网桥 EnspBridgeE 每轮 step 末尾的自动拉截图恒 DOWNLOAD-FAIL。
- **原因**：拉图竞态。
- **解法**：手动 pull 即可；不影响执行，step 本身照常完成。
