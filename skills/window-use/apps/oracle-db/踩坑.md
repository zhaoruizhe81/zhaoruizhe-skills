# Oracle 数据库(服务端)装配与排障 · 实测沉淀(2026-10-19,windowpc)

面向剩余实验(查询视图/索引完整性/PL-SQL 触发器)复用的服务端事实与坑。

## 静默安装(Oracle AI Database 26ai Free,Windows)
- 下载 zip →解压到 `C:\temp\free_temp`(含 setup.exe、FREEInstall.rsp、DB.cab)。
- 改 `FREEInstall.rsp`(在解压根目录,**没有 response/ 子目录**):INSTALLDIR、PASSWORD、LISTENER_PORT=0、CHAR_SET=AL32UTF8。所有参数不得留空。
- 静默安装:写一个 .cmd(`setup.exe /s /v"RSP_FILE=<rsp绝对路径>" /v"/L*v <日志>" /v"/qn"`)用 PowerShell `Start-Process -WindowStyle Hidden` 启动(SSH 后台 & 会被杀,见 remote/远程坑.md)。
- 安装 15~25 分钟:先装软件,后 DBCA 静默建库。完成标志 = setup.log 出现 `Installation success or error status: 0`;服务 `OracleServiceFREE`、`OracleOraDB23Home1TNSListener` RUNNING 也可判活(比日志行早)。
- 装完固定产物:SID=FREE(不可改),PDB=FREEPDB1,OracleHome=`<INSTALLDIR>\dbhomeFree`,sqlplus 在 `<OracleHome>\bin\sqlplus.exe`。DBCA 图形界面在 Free 版没有自建库入口——题目要"DBCA 创建 YGGL 库"时,以 FREEPDB1 里建 YGGL 用户/表空间替代。

## 坑
1. **GBK 乱码 / ORA-01756**:Git Bash 里 sqlplus 跑含中文的 .sql,必须 `export NLS_LANG=AMERICAN_AMERICA.AL32UTF8`(sqlplus 按 NLS_LANG 解析脚本字节;Windows 控制台显示乱码只影响显示,不影响存储)。
2. **表建错 schema**:脚本里 `create table Employees` 落到当前登录用户(SYSTEM)。一律带 `yggl.` 前缀;误建后 `drop table system.<t> cascade constraints` 清理。
3. **外键删除顺序**:先子表(Salary)后主表(Employees),否则 ORA-02292。
4. **查对象真身**:`select con_id, owner, object_name from cdb_objects where object_name='<大写名>'` 一眼定位对象落在哪个容器/用户;只查 all_tables 前记得先 `alter session set container=FREEPDB1`。
5. **密码含 # 在连接串里**:命令行 `sqlplus "system/\"Oracle#2026Lab\"@..."`(双引号包密码)。YGGL 实验库密码 yggl123 无此问题。
6. **char(n) 按字节计长,UTF-8 一个汉字 3 字节(2026-11-06 实付 ORA-12899)**:Name char(10) 只能放 3 个汉字(9 字节),5 字姓名直接报 ORA-12899。建表含中文数据时要么缩短中文值,要么建表用 char(10 char)/varchar2(10 char)(字符语义)。实验二题20 经视图插中文姓名实踩,截图留证。
