## 1. 会话桥接与计划任务

### 1.1 SSH 会话碰不到桌面
- **症状**：脚本执行"成功"，但屏幕上什么都没发生；截屏全黑或失败；CopyFromScreen 抛异常。
- **原因**：Windows 的 SSH 会话运行在 session 0（隐藏会话），与控制台桌面（session 1）隔离。
- **解法**：用计划任务做跳板——`schtasks /create /tn X /tr <action> /sc once /sd 2099-01-01 /st 00:00 /it /f`，`/it`（interactive token）让任务运行在已登录用户的桌面会话；随后 `schtasks /run /tn X` 手动触发。
- **注意**：`/sd 2099-01-01` 必须设置。只给 `/st` 时（如 /st 23:57），到达该时刻任务会**自燃执行一次**——本案例中它凌晨自动重启了程序、覆盖了截图，排障数小时。
- **前提**：目标 PC 必须已登录桌面（有 explorer.exe）。用 `tasklist | findstr explorer` 判断；只看到 LogonUI.exe 说明在锁屏/未登录，交互式任务不会执行。

### 1.2 控制台窗口抢焦点 + 污染截图
- **症状**：每次任务运行屏幕上弹出黑色 cmd 窗口；截图里总有它；按键偶尔"消失"。
- **原因**：任务动作经 cmd 批处理启动时必然带控制台窗口；控制台弹出时会抢键盘焦点，导致发往目标窗口的按键落到控制台里。
- **解法**：任务动作直接用 `pythonw.exe <script.py>`（GUI 子系统，无窗口）。若必须用 .bat，改用 VBS 的 `WScript.Shell.Run "...", 0, False` 包一层。绝不 `.bat → python.exe`。

### 1.3 schtasks /tr 引号地狱
- **症状**：`/tr "带空格的路径 参数"` 经多层 shell 转义后报 exit 5 / 参数被拆散 / 路径反斜杠丢失。
- **解法**（按优先级）：
  1. 任务动作 = 单一脚本路径，**不带参数**（参数经文件传递，见 driver-pattern）；
  2. 路径选择无空格的位置；
  3. 必须带引号时写进 `.ps1` 文件上传执行，绝不内联；
  4. PowerShell 里用单引号包 `schtasks /tr '"exe" arg'` 最稳。

### 1.4 强杀进程的连环后果
- **症状**：`taskkill /F` 杀掉 SSMS/Office 后重启，弹出"恢复的文件"对话框，阻塞一切后续操作（对象资源管理器不连接、菜单打不开）。
- **解法**：重启后用 UIA 找该对话框的按钮直接点击（如"不恢复(D)"——注意按钮加速键别猜，读按钮全名）。预防：优先优雅关闭；杀进程前先把对话框处理流程写好。

### 1.5 多实例堆积与文件锁
- **症状**：向导类程序第二次启动时报"文件已被其他用户以独占方式打开"；或窗口越积越多。
- **原因**：每次失败的运行都会留下一个未关闭的实例；向导打开数据文件时是独占锁。
- **解法**：启动前枚举该程序所有顶层窗口并全部关闭（先点掉窗口内的 OK/错误弹窗，再 close()，close() 失败就点 Cancel/关闭）；仍杀不掉就 `taskkill /F /IM 程序名`。启动后断言实例数量为 1。

## 2. Git Bash 与命令行编码陷阱

远程是 Git Bash（POSIX 语法）时，本地引号要经过 [Mac shell → ssh → 远程 bash → cmd/程序] 多层解析，这是本项目最大的时间黑洞。

### 2.1 反斜杠路径被吃
- **症状**：`C:\Users\master\auto` 传到远端变成 `C:Usersmasterauto`，甚至 `\a` 变成响铃字符（BEL）。
- **规则**：远端 bash 中**未加引号**的反斜杠路径会被转义处理。加双引号可保住反斜杠；但某些程序（如 sqlcmd 的 `-i` 参数）收到正斜杠形式 `C:/...` 时反而报"-E 与 -U/-P 互斥"这类怪错。
- **解法**：逐个程序实测，写进备忘。sqlcmd 用 `-i "C:\path\file.sql"`（双引号反斜杠）。最稳的办法：**复杂命令写成脚本文件上传执行**，命令行只留 `文件路径` 一个词。

### 2.2 内嵌单引号提前闭合外层引号
- **症状**：本地组装的远程命令字符串在中间被拆成两段，报"unrecognized arguments"。
- **原因**：外层用单引号包裹整条远程命令时，命令内部的任何一个单引号都会提前闭合它。
- **解法**：同样的结论——写成文件。禁止在一条内联命令里嵌套两层以上引号。

### 2.3 中文输出乱码（GBK）
- **症状**：schtasks/sqlcmd 的中文输出是一串 `????`。
- **解法**：远端 `| iconv -f GBK -t UTF-8` 转码；sqlcmd 加 `-f 65001` 并确保输入文件带 UTF-8 BOM。判定成功与否尽量基于**文件/数据库状态**而非解析中文输出（例如查 `sys.tables` 而不是解析"命令已成功完成"）。

### 2.4 SQL 文件编码
- **症状**：SSMS 打开 SQL 文件中文变问号。
- **解法**：SQL 文件写 UTF-8 **带 BOM**（`\xef\xbb\xbf` 前缀），SSMS 与 sqlcmd 都能正确识别。

### 2.5 sqlcmd -Q 里的引号
- **症状**：`-Q "... LIKE N'%x%'"` 的引号经多层转义后报语法错误。
- **解法**：避免在 SQL 字符串字面量里用引号——用 `LIKE N[%]x%` 之类技巧，或干脆全量查出后在本地过滤。复杂 SQL 一律走 `-i` 文件。

## 3. pywinauto UIA 陷阱

### 3.1 嵌入式对话框枚举不到（本项目最大坑）
- **症状**：屏幕上明明开着对话框（截图可见），`Desktop(backend="uia").windows()` 枚举不到它，按标题匹配永远失败。
- **原因**：VS shell/WPF 应用的很多"对话框"不是独立顶层窗口，而是**主窗口树内的子面板**（其按钮出现在主窗口 descendants 里）。
- **解法**：在 `主窗口.descendants(control_type="Button")` 里按名称+位置找控件。例如同名"连接"按钮：工具栏的在最左侧（left<100），对话框里的在屏幕中部（left>300），用矩形过滤区分。
- **教训**：先写一个 `winlist2` 诊断命令——枚举所有顶层窗口及其按钮名——再决定匹配策略。**先取证，再写匹配。**

### 3.2 UIA Name 与显示文本不一致
- **症状**：控件在屏幕上显示"选择"，`window_text()` 返回空或别的。
- **解法**：不要按显示标题匹配。改按**特征控件**定位（如"窗口里存在名为 X 的按钮"），或按控件矩形位置过滤。

### 3.3 树节点重命名陷阱
- **症状**：操作树节点后弹出的是"撤销/剪切/粘贴"**文本编辑菜单**，节点进入重命名编辑态。
- **原因**：`click_input()` 点在已选中的节点上等价于"再次点击"=进入重命名；或焦点本来就在编辑框里，Shift+F10 弹的是编辑框菜单。
- **解法**：
  1. 移焦点用**真鼠标点击另一个不同节点**（不同节点不会触发重命名）；
  2. 再用 UIA `node.select()` 选中目标（不经过鼠标，绝不触发重命名）；
  3. `select()` **不会移动键盘焦点**——随后必须 `node.set_focus()`（且要防它静默失败）；
  4. 再 Shift+F10 弹节点菜单。
- **兜底**：出问题时先按 ESC（取消重命名），并用 sqlcmd/API 确认数据没被改坏。

### 3.4 上下文菜单项枚举不到
- **症状**：右键/键盘呼出的上下文菜单在截图里可见，但 `descendants(control_type="MenuItem")` 枚举为空。
- **原因**：弹出菜单要么不在主窗口树里，要么枚举时机不对。
- **解法**（按可靠度排序）：
  1. **菜单保持打开时截图，用眼睛读位置，用鼠标坐标点击**——菜单在 pythonw 模式下跨命令保持打开，这是最可靠的路径；
  2. 加速键字母：截图确认后盲发（如"设计(G)"发 g），但必须先截图确认字母；
  3. 方向键导航（DOWN/RIGHT/ENTER）：项目顺序必须先截图确认，顺序猜错会点到"删除/重命名"这类危险项。
- **纪律**：任何进入菜单的操作，**发键之前先截图看一眼**；每个键之间留 1.5~2.5 秒。

### 3.5 set_edit_text 抛 COMError
- **症状**：`set_edit_text()` 报 `COMError (-2147220992)`，值写不进去。
- **解法**：改用 `ed.click_input()` 聚焦 → `^a` 全选 → 剪贴板粘贴 `^v`。对 WPF/自绘编辑框，粘贴比 ValuePattern 可靠得多。

### 3.6 UIA select() 不移焦点
- **症状**：`node.select()` 后发 Shift+F10，弹出的却是另一个（此前聚焦的）元素的菜单。
- **解法**：select 只改选中项。移动键盘焦点用真鼠标点击，或 `node.set_focus()`（要 try/except 包裹并验证生效，它可能静默失败——验证方法：先截图看弹出的菜单属于谁）。

### 3.7 菜单加速键跨版本不可靠
- **症状**：按文档/经验发的加速键字母（如还原=R）无效果，菜单停在接受第一个字母的状态，随后的按键全部错位。
- **解法**：永远截图读菜单。有的版本菜单项没有下划线字母；有的"还原"在"任务"子菜单里第二项。**打开菜单 → 截图 → 按坐标用鼠标点**，三步走。

## 4. 键盘、鼠标与输入

### 4.1 send_keys 吞括号
- **症状**：往表格里键入 `(030)30074321`，落到单元格的是 `03030074321`——两个括号消失。
- **解法**：含特殊字符或中文的文本一律走剪贴板：`set_clip(v); send_keys("^v")`。逐字段粘贴，每字段后 `{TAB}`。

### 4.2 网格新行追加了 "NULL" 前缀
- **症状**：编辑网格里录入后值变成 `NULL0001`。
- **原因**：点击单元格后单元格编辑器带着 NULL 占位文本，键入变成了追加。
- **解法**：点击单元格 → `^a` 全选 → 粘贴覆盖。逐字段走。

### 4.3 长序列键盘导航不可靠
- **症状**：`{DOWN}{DOWN}{RIGHT}{DOWN}{ENTER}` 想在菜单里导航，结果弹出的是完全无关的对话框（甚至是重命名确认）。
- **原因**：焦点漂移 + 子菜单展开动画期间按键丢失 + 项目顺序猜错。
- **解法**：方向键序列是最后手段。先截图确认每一项的位置，用**鼠标坐标点击**。若必须用键盘，每个键单独 send 并截图确认。

### 4.4 Enter 是菜单里的默认按钮
- **症状**：选完下拉项补发一个 `{ENTER}` 收尾，结果触发了"下一步"并弹出校验错误。
- **原因**：下拉其实已经关闭，ENTER 打到了对话框的默认按钮。
- **解法**：select/点击列表项后**不要补 ENTER**；枚举确认列表项已消失再继续。

## 5. 进程与状态管理

### 5.1 多命令的状态传递
- **解法**：子命令写入 `next_cmd.txt`（驱动脚本无参数启动时读取它）。驱动每条命令结束时写 `DONE <cmd>` / `FAIL <cmd>` 到 `gui.log`，编排端轮询最后一行。FAIL 时自动截错误现场图。

### 5.2 残留实例与文件锁
- **症状**：向导第二次运行时报文件被独占占用。
- **解法**：见 1.5。清理函数模式：轮询枚举窗口 → 窗口内先点 OK 类弹窗 → close() → 失败则点 Cancel/关闭 → 仍失败 taskkill。给清理循环加轮数上限，防死循环。

### 5.3 独占访问类操作（如数据库还原）
- **症状**：GUI 里点确定后报"数据库正在使用"。
- **原因**：应用里打开的查询标签页各自持有连接。
- **解法**：**保持 GUI 对话框打开**，通过旁路（sqlcmd 的 `KILL session` / 关闭标签页）释放连接，然后再点确定。对话框开着不影响 SQL 旁路执行。
- **注意**：杀会话/关标签的键序同样要截图确认；SQL 旁路跑完后再点 GUI 的确定按钮。

### 5.4 冷启动时间差异
- **症状**：脚本在应用启动完成前就去找控件，随机失败。
- **解法**：轮询等待特征控件/进程出现（如每 5 秒查一次，最长 200 秒），不要固定 sleep。首次启动比后续启动慢很多（CPU 被占满时连截屏都要 30 秒），每步动作后轮询产物文件（PNG/日志标记）而不是睡固定时长。

## 6. 验证与调试纪律

### 6.1 截图闭环是最高法则
每执行一个动作，立刻全屏截图并下载查看。90% 的"按键没反应"通过一张截图就能定位（焦点在别处/弹窗挡住/菜单没开）。

### 6.2 平行通道验证 ground truth
GUI 截图给人看，SQL/API/文件系统验证真相。例如导入是否成功，用 `SELECT COUNT(*)` 而不是只看向导的成功页。

### 6.3 诊断命令先行
反复失败时，先写一个**只读诊断子命令**（枚举窗口标题、枚举控件树、dump 文本）跑一次，基于证据修匹配逻辑。猜测式修改会成倍浪费时间。

### 6.4 一次只改一个变量
每轮迭代只调整一个假设（改匹配方式 / 改等待方式 / 改坐标），否则无法归因。

### 6.5 危险操作前先验证数据
重命名/删除类对话框出现时（尤其键盘导航误触时），先停下，用 SQL 查询确认数据现状，再决定点哪个按钮。ESC 取消编辑态永远安全。
