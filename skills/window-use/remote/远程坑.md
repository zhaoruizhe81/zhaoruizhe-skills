# 远程场景专属坑（§1-§11；本机直跑不存在这些问题；公共坑见根目录 踩坑清单.md）

每一项都是真实排障付出过时间的。症状 → 原因 → 解法。

> **失败排障入口**：SKILL.md 的"坑点速查表"按症状索引了本文件条目（远§N）。
> 先用症状/报错关键词 grep 定位，再读对应节全文，按解法做，不自创——
> 同一症状失败两次还没查过 = 违规（规则见 SKILL.md"失败处理阶梯"）。

## 1. session-0 桥接

### SSH 会话碰不到桌面
- **症状**：SSH 里跑 GUI 脚本"成功"，屏幕上什么都没发生；截屏全黑；CopyFromScreen 抛异常。
- **原因**：Windows 的 SSH 会话运行在隐藏的 session 0，与控制台桌面隔离。
- **解法**：计划任务做跳板——`schtasks /create /tn X /tr <动作> /sc once /sd 2099-01-01 /st 00:00 /it /f`，
  `/it` 让任务跑在已登录用户的桌面会话；之后 `schtasks /run /tn X` 手动触发。
- **前提**：目标 PC 已登录桌面（有 explorer.exe）。`tasklist | findstr explorer` 判断；
  只有 LogonUI.exe 说明在锁屏，交互式任务不会执行。

### /sd 2099 必须设置
- 只给 `/st 23:57` 不给 `/sd` 时，到达该时刻任务会**自燃执行一次**——曾发生凌晨自动重启程序、
  覆盖截图，排障数小时。`/sd 2099-01-01` 让 once 触发器永不自燃，只允许手动 `/run`。

### 任务动作必须用 pythonw.exe
- `.bat` 包装或 `python.exe` 会弹黑色控制台窗口：抢键盘焦点（按键"消失"）、污染每张截图。
- 动作 = `pythonw.exe <驱动绝对路径>`，**不带参数**；参数经 `next_cmd.txt` 文件传递。

### schtasks /tr 引号地狱
- `/tr "带空格路径 参数"` 经多层 shell 转义后报 exit 5 / 参数拆散 / 反斜杠丢失。
- **解法**（按优先级）：① 动作 = 单一无参数脚本路径；② 路径避开空格；
  ③ 必须带引号的命令写进 `.ps1` 上传执行，绝不内联；④ PowerShell 里单引号包 `'"exe" arg'` 最稳。

### 冷启动/登录状态
- 首次动作前确认：桌面已登录、目标软件已打开或由脚本启动并**轮询**其特征控件出现
  （每 5 秒查一次，别固定 sleep——CPU 忙时连截屏都可能要 30 秒）。

### SSH 里起 GUI 程序(含 Start-Process)一律不可见
- **症状**：`Start-Process xxx.exe` 返回成功、tasklist 里进程也在,桌面上却什么都没出现。
- **原因**：SSH 会话整体在 session 0,从它派生的任何 GUI 进程(包括 PowerShell Start-Process)都落在 session 0。
- **解法**：GUI 程序必须经计划任务桥启动——push 一个 `subprocess.Popen([exe, ...])` 的脚本走 `pt.py step`。
  实付：SQL Developer 首启从 SSH Start-Process,进程在、窗口无,空等数分钟(2026-10-19)。

### 长后台任务(大下载/安装)用 PowerShell Start-Process,别用 nohup &
- **症状**：`ssh 'cd dir && nohup curl -o big.zip URL & disown'` 之后文件不增长甚至不存在、无 curl 进程、err 为空。
- **原因**：ssh-skill exec 会话结束清理子进程树,nohup/disown 保不住;且 `&&`+`&` 复合命令经多层解析偶发整条不执行。
- **解法**：
  `MSYS_NO_PATHCONV=1 ssh <host> 'powershell -c "Start-Process -WindowStyle Hidden curl.exe -ArgumentList \"-sSL\",\"-o\",\"C:\path\f.zip\",\"<URL>\""'`
  ——Start-Process 建立独立进程,不受会话退出影响,1.4GB 实测稳定拉完;进度轮询用 `ls -l` 看文件大小(2026-10-19)。

## 2. Git Bash / 传输层（Mac → 远端 Git Bash 时）

远程 shell 是 Git Bash（POSIX）时，本地引号要过 [Mac shell → ssh → 远端 bash → cmd/程序] 多层解析，
这是远程场景最大的时间黑洞。

### 斜杠开关被转成路径
- **症状**：`schtasks /run` 报找不到 `C:/Program Files/Git/run`；`taskkill /F /IM x.exe` 报"无效参数 - 'F:/'"（同一根因,2026-10-19 实付）。
- **解法**：`MSYS_NO_PATHCONV=1 schtasks /run ...`（pt.py 已内置）；taskkill 类用 `MSYS_NO_PATHCONV=1 ssh <host> 'cmd /c "taskkill /F /IM x.exe"'` 包一层 cmd 最省心。

### 反斜杠路径被吃
- **症状**：`C:\Users\master\ptauto` 传到远端变 `C:Usersmasterptauto`，`\a` 甚至变响铃符。
- **解法**：远端命令里一律用**正斜杠**路径（`/c/Users/master/ptauto`）；复杂命令写成文件上传执行。

### 内嵌单引号提前闭合外层引号
- 外层单引号包整条远程命令时，内部任何一个单引号都会提前闭合它 → "unrecognized arguments"。
- **解法**：禁止内联嵌套两层以上引号，全部走文件。

### SFTP 只收 home 相对路径
- **症状**：`upload local C:/Users/master/ptauto/x.txt` 失败。
- **解法**：远端参数一律写相对 home 的路径：`ptauto/x.txt`（pt.py 已内置）。

### 中文输出乱码（GBK）
- schtasks 等的中文输出是一串 `????` → 远端 `| iconv -f GBK -t UTF-8`（pt.py 已内置）。
- 判定成败尽量基于文件/日志状态（gui.log 的 DONE/FAIL），别解析中文输出。

### Mac 端环境
- 系统 python3 可能缺 paramiko → 用 miniconda 的 python（pt.py 的 PY 常量）。
- Mac 端长命令前先 `cd` 项目目录（shell 状态会重置）。

## 3. 远程排障纪律

1. 桥是否通：`python3 remote/pt.py send shot probe1` 一条命令验证全链路（投递+触发+轮询+拉图）。
   ⚠ 裸 `schtasks /run` 已不能当验证手段——next_cmd.txt 读后即删，无投递命令时驱动只记一条 FAIL parse。
2. 每条命令 DONE/FAIL 以 gui.log 的标记行为准（pt.py send 已按 §5 协议轮询）；
   FAIL 时驱动自动存 `error_<cmd>_<HHMMSS>.png`（时间戳命名），先看图和 traceback 再改。
3. 超时后不要立刻重发——先截图看现场（可能命令实际已生效，重发会二次点击）。

## 4. 提权任务与实例管理（2026-10-14 MySQL 8.0 + Navicat 实战新增）

### 要操作提权窗口（服务管理器/管理员 cmd）→ 驱动任务注册 /rl HIGHEST
- **症状**：非提权驱动读不到服务管理器 MMC 的控件、点不动管理员 cmd（UIPI：低完整性
  级别进程无法向高完整性级别窗口发输入）。
- **解法**：`remote/create_task_elevated.ps1`（比基础版多一个 `/rl HIGHEST`）。驱动及其
  子进程（cmd.exe / mmc.exe）全部继承提权：无 UAC 弹窗、什么窗口都能点；spawn 的 cmd
  标题带"管理员:"前缀，写实验报告反而需要。普通应用任务用基础版即可。

### schtasks /run 被 IgnoreNew 静默跳过
- **症状**：/run 回"成功: 尝试运行"，但 gui.log 迟迟没有新 START；偶发整轮不执行。
- **原因**：上一个 pythonw 实例未退出时，默认 MultipleInstances=IgnoreNew 让 /run 静默跳过。
  驱动里做全树 UIA 遍历（大列表要几分钟）最容易占住实例。
- **解法**：重试前 `MSYS_NO_PATHCONV=1 cmd /c "taskkill /F /IM pythonw.exe"`；驱动只用
  定向 UIA 查询（踩坑清单 #15）。
- **触发失败不再静默（现行）**：pt.py 现在会检测 schtasks /run 本身的失败
  （exit code + "错误/ERROR"关键词），触发失败立即 FAIL 并 cat 日志——
  不再空轮询 240s 后 TIMEOUT。

### 任务启动有 20~25 秒延迟
- **症状**：/run 后日志"迟迟"没动静，其实任务计划服务还没把进程拉起来。
- **解法**：轮询预算 = 启动延迟 + 命令时长。pt.py 默认 240s（`--timeout` 可调），
  慢命令（服务启停/软件冷启动）再加大。

### 服务操作后用服务真状态收尾（net start 报 1053 ≠ 失败）
- SCM 默认等 30s 就报"错误 1053"，慢服务仍在后台继续启动。判定成败用
  `sc query <svc>` 轮询（驱动内置 `svc_state/svcwait`），别拿命令回显当结论。

## 5. 编排端轮询协议（pt.py send 已按此实现，改代码前先读）

### 新版 pt.py 全局选项必须在子命令前
- **症状**：`pt.py step x.py --timeout 300` 报 ARG-ERROR,--timeout 被当作截图名/位置参数吞掉。
- **原因**：argparse REMAINDER 把子命令后的所有内容当位置参数。
- **解法**：`pt.py --timeout 300 step x.py`（2026-11-06 实付一轮）。


1. **每轮跑命令前清空 gui.log 并回读确认为空（清不空立即 FAIL）** —— 轮询只看本轮输出，
   从源头堵死上一轮残留标记污染。
2. **标记行以 `[HH:MM:SS] ` 开头，FAIL 后还跟多行 traceback** —— 必须
   `grep -E "\] (DONE|FAIL)" gui.log | tail -1` 整份过滤后取最后一条；
   直接 `tail -1` 或 `case "DONE*"` 永远匹配不上，表现为"明明失败却干等超时"。
3. FAIL 时先 `cat gui.log` 读 traceback + 拉 `error_<cmd>_<HHMMSS>.png` 看现场，再改一个变量重试。

## 6. 驱动与传输的运行期故障（Lab4 实战新增）

### 驱动实例挂起 → schtasks /run 静默失败
- **症状**：`schtasks /run` 返回乱码警告（GBK 解码后是"警告: 任务已在运行"），脚本命令根本没执行，而输出被 `>/dev/null` 吞掉时更难察觉。
- **原因**：上一次的 pythonw 驱动还挂着（脚本内的重试循环/长 sleep 没跑完），任务处于"正在运行"状态。
- **解法**：`tasklist | grep pythonw` 查挂起实例，`taskkill /F /PID` 杀掉后再触发；触发后用 `tail gui.log` 确认出现新的 `START` 行才算真的跑了。**判定成功永远以 gui.log 新增行为准，不以 schtasks 返回为准。**

### next_cmd.txt 的陈旧内容会被重跑
- **症状**：只 push 了新脚本、直接 `schtasks /run`（没走 send 写 next_cmd），驱动执行的是**上一次的旧脚本**；甚至挂起驱动恢复后把早已过期的脚本再跑一遍，把拓扑改乱。
- **解法**：触发前**先覆写 next_cmd.txt 为本轮命令**（`echo 'script xxx.py' > next_cmd.txt`），或统一走 pt.py send；触发后核对 gui.log 的 START 行确实是预期脚本。
- **工具层防护（现行）**：win_gui_driver 栈的驱动读 next_cmd.txt 后立即删除（防重放），
  手工 `schtasks /run` 不再重放旧命令；"覆写+核对 START"纪律仍建议保留——
  mysql_lab 等专用桥不享受此防护。

### pt.py send 的旧 DONE 污染已从源头防住
- **症状**：send 秒回 "OK" 但实际什么都没发生（或还没发生）。
- **原因**：日志里残留着上一次同名命令的 DONE 行，轮询一进来就误判。
- **现行机制**：pt.py 触发前先清空 gui.log 并回读确认为空（清不空立即 FAIL，
  从源头堵死陈旧 DONE），再投递+触发；轮询用 START 守卫（带参命令要求出现
  本轮 START 行）+ 30s 退化路径兜底；触发命令（schtasks /run）不重试，
  防止远端已执行而回包丢失时二次触发。

### SFTP 通道死亡但 exec 正常：用 HTTP 服务绕过拉截图
- **症状**：`download` 连续失败而 `exec` 一切正常（SFTP 子系统挂了/限流）。
- **解法**：在 PC 上起临时 HTTP 服务把截图目录暴露出来，Mac 用 curl 拉：
  `python -m http.server 8080 --directory <shots目录>`（SSH 会话启动需 nohup 后台），Mac `curl http://<PC-IP>:8080/<文件名>`。用完记得杀掉进程。

## 7. 传输与轮询的静默失败（Lab4 v2 实付）

### SFTP upload/download 瞬断
- **症状**：同一会话里 upload/download 偶发失败（kex_exchange_identification timeout、
  download_failed），隔几秒重试就好；一次长会话里出现 3-4 次。
- **解法**：pt.py 的 ssh/up/down 已内置 2 次重试（间隔 4s）。仍失败时走 SSH exec 兜底
  通道传文件：本地 `base64 < file`，远端 `printf %s <b64> | base64 -d > /c/.../path`
  （Git Bash 路径用 /c/ 形式；用 printf 别用 echo，长 base64 会被 shell 处理歪）。

### 陈旧 DONE 假成功（截断竞态）
- **症状**：`send script x.py` 报 OK，但脚本根本没执行（gui.log 里没有本轮 START）。
- **原因**：send 开头用 `> gui.log` 截断日志；截断未生效时，上一轮残留的
  "DONE script" 被裸 `DONE <命令字>` 匹配 → 假成功，后续 pull 拉到旧图或不存在的图。
- **解法**（现行三层）：① 触发前清空 gui.log 并回读确认为空，清不空立即 FAIL
  （从源头堵死陈旧 DONE）；② **START 守卫**——带参数的命令（script x.py / shot y）
  必须先看到本轮带该参数的 "START" 行，其后的 DONE/FAIL 才被承认；30s 内没见到带参
  START 就退化为"出现过该命令的 START 即可"（30s 退化路径在截断失败场景防护有限，
  截断失败主要靠①的回读确认堵住）；③ step 触发前删除远端同名 shots/<name>.png，
  落地后校验 PNG 魔数与非零大小（pull 同样校验）——公#29/A7/本节旧图的实付事故
  已在工具层防住。命中陈旧 DONE 时会打印可读格式的 verdict 详情
  （忽略了哪条、为何）并继续等真跑。

### §2.2 PowerShell 内联转义吃掉重定向/变量，Start-Process 静默没起（2026-10-26 实付）
- **症状**：`ssh host "powershell -c \"Start-Process ... 2>\$null\""` 回显正常但服务没起（netstat 计数=0），
  curl 拉文件全部为空。
- **原因**：`2>$null`、`$_` 这类记号经 Mac shell→ssh→Git Bash→powershell 多层解析后被吃掉/拆散，
  整条命令静默变形——正是本文件 §2 "必须带引号的命令写进 .ps1 上传执行" 的活案例。
- **解法**：长 Start-Process 命令一律 printf 写 .ps1 → scp 上传 → `powershell -ExecutionPolicy Bypass -File` 执行；
  起服务后必须 `netstat -ano | grep :端口 | grep LISTEN` 计数验证，别信回显。

### §2.3 curl -s 拉图失败是全静默的（2026-10-26 实付）
- **症状**：`curl -s -o x.png url` 连接失败/404 时不写文件也不报错，`ls` 一看目录全空才发现通道没通。
- **解法**：`-s` 改 `-sS`，且每批拉完必 `ls -la` 数文件、看大小（全屏 1920×1080 截图正常 ~100KB+，
  335 字节=404 页面，几 KB=黑屏/空白页）。

### §2.4 shots 目录历史撞名：拉回的可能是几个月前的旧图（2026-10-26 实付）
- **症状**：shots 目录积累了大量历史任务截图（w*.png、a*.png、b*.png 等单字母前缀几乎全被占用），
  新任务 shot("w1") 与旧文件同名——若新截图实际没存成，pull 拉回的是旧图，肉眼难辨。
- **解法**：每个任务用独立前缀（日期/任务名）命名截图；拉回后核对文件 mtime 是否为本轮时间；
  关键判断前按内容验收（公#29 的批量版）。
- **工具层防护（现行）**：pt.py step 触发前删除远端同名 shots/<name>.png，落地后校验
  PNG 魔数与非零大小（pull 同样校验）——公#29/A7/本节旧图的实付事故已在工具层防住。

### §2.1 tasklist 过滤参数经 Git Bash 双层引号静默失败（2026-10-25）
`ssh exec 'cmd.exe /c "tasklist /FI \"IMAGENAME eq stats.exe\""'` 这类嵌套引号会被 Git Bash 吃掉，
只回显 cmd banner 和提示符，**看起来执行了其实什么都没查**——极易误判"进程不存在"
（实付：SPSS 明明在跑却被判死亡，浪费一轮排障）。判进程用无参数管道：
`tasklist | grep -i 名字`；要过滤就写进 .ps1 上传执行。

## 8. 远程关机/重启（2026-10-26 实付）

### 发出 shutdown 到实际断连有 20~40 秒窗口
- **症状**：`shutdown /s /t 10` 发出后 ~18s 用 SSH 探测仍能连上，误判"没生效"想重发。
- **原因**：/t 计时结束后 Windows 还要走完关机流程（结束会话→停服务→断电），SSH 服务在流程后段才停。
- **解法**：判定断连等 ≥40s 再探，或 ping + ssh 双通道；期间误发的第二条关机命令无害（只是叠加计时）。
  多层转义下发 shutdown 时 `/s /t` 记得 `MSYS_NO_PATHCONV=1`；/c 注释带中文极易被转义弄坏，
  干脆不带注释直接 `shutdown /s /t 15 /f`。

### exec 通道 stdout 有截断上限（256KB），base64 传大文件不可行（2026-10-27 实付）
- **症状**：`exec "base64 大文件"` 拿回的 JSON 里 `truncated: true`，解码只得到 ~16KB
  的折叠片段（头 3/4 + 尾 1/4）；SFTP download 同时瞬断时，文件传不出来。
- **原因**：ssh_skill exec 对 stdout 有总量上限 MAX_RESULT_BYTES=256*1024（256KB）；
  超限按 16KB→…→512B 分级折叠保留（头 3/4 + 尾 1/4），exec 只适合小输出。
- **解法**：大文件走 HTTP——把 `Start-Process -WindowStyle Hidden -PassThru python.exe -ArgumentList
  "-m","http.server","<port>","--directory",<目录>` + PID 落盘写进 **.ps1 上传执行**（§2.2），
  `netstat -ano | grep <port>` 验证 LISTEN（§2.1 无嵌套引号写法），Mac `curl -sS` 拉取后
  `md5` 对照 PC 端 `md5sum`，再按 PID 用 ps1 `Stop-Process -Id` 杀服务。
- **注意**：`cmd /c "taskkill …"` 嵌套引号隔层被吞（§2.1 同坑二次踩）：杀 PID 一律写 ps1。

## 9. 一台 PC 多套桥共存：路由与直驱模式（2026-10-28 数据库实验一实战新增）

### 现象：windowpc 上有两套已部署的桥
- `ptauto/` + 计划任务 `PtGuiBridge`（标准 win_gui_driver.py 栈，配套 pt.py）。

### 一次性桥直驱模式（优先用 pt.py；确需直驱看修正版配方）
⚠ **优先走 pt.py**（`remote/pt.py --host <host> --task <任务名> --auto <远端AUTO名> send/step ...`，
一条命令全链路）。确需直驱时用下面的修正版——旧配方有两个坑：`$AUTO` 未定义（展开成空串）；
裸 `printf` 写 next_cmd.txt 不转义，反斜杠路径会被吃。桥读 next_cmd.txt 按 shlex 解析，
写入侧必须先 **shlex.quote 预转义**（与 pt.py 的转义协议一致）：
```zsh
AUTO=/c/Users/master/ptauto                                     # 先定义（MysqlLab 桥对应 /c/Users/master/auto）
BASE=$(ssh windowpc "cat $AUTO/gui.log" | wc -l)                # 记行数（gui.log 只有时分秒没日期，靠行数差分）
CMD=$(python3 -c 'import shlex,sys; print(" ".join(shlex.quote(a) for a in sys.argv[1:]))' \
      script w01.py)                                            # 参数逐个 shlex.quote 后拼行
printf '%s' "$CMD" | ssh windowpc "cat > $AUTO/next_cmd.txt"
ssh windowpc "MSYS_NO_PATHCONV=1 schtasks /run /tn MysqlLab"    # 触发不重试：远端已执行时二次触发=二次点击
# 轮询 ssh "tail -n +$((BASE+1)) gui.log" 直到出现 DONE/FAIL（协议同 §5）
scp "windowpc:C:/Users/master/AUTO/shots/$name.png" ./          # 拉截图
```
- 成败只看 gui.log **新增行**里的 DONE/FAIL（§4 的 IgnoreNew 与 §5 的过滤规则在这里同样适用）。
- 命令参数按空格 split，含空格文本（SQL、中文）走 `sqlc <shot> <语句>`（剪贴板通道，
  中文可正确入库）或 `script x.py`。

### 直接 scp 拉文件：SFTP 路径用 Windows 风格 `C:/Users/...`
- **症状**：`scp windowpc:/c/Users/master/AUTO/shots/x.png .` 报 No such file or directory，
  但 `ssh windowpc "ls /c/Users/..."` 正常。
- **原因**：ssh 命令走远端 Git Bash（认识 /c/），SFTP 子系统不经过 shell，只认 Windows 路径。
- **解法**：`scp "windowpc:C:/Users/master/AUTO/shots/x.png" .`（§2 的"home 相对路径"是
  pt.py 内置封装的规则；裸 scp 时用 C:/ 风格）。

### 复杂动作走 script 通道
一条命令表达不了的序列（右键→等→点菜单→填框→保存，带重试自愈）写成独立 .py
scp 到 `$AUTO/scripts/`，next_cmd 写 `script x.py`。桥会注入 shot/set_clip/log/Desktop/
send_keys/pywinauto.mouse 等环境；脚本内 `import pywinauto.mouse as mouse` 用
press/release（该模块**没有 down/up**）。一个脚本 = 一个原子动作，内部可带重试循环
（如"右键→点菜单项被订阅弹窗打断"的 for 重试），结尾 shot 同名截图供 step 拉回。

## 11. 安全与并发备忘

- **提权桥 = 本地静默提权通道**：任何以同用户身份运行的进程，写 next_cmd.txt +
  `schtasks /run /tn PtGuiBridge` 即可让驱动以 HIGHEST 完整性执行任意代码，
  全程无 UAC。PC 上不要让不可信程序与当前用户同权限运行。
- **凭据明文留存**：login / 带密码 SQL 会经三处明文落盘——/tmp/next_cmd.txt（Mac）→
  ptauto/next_cmd.txt（PC）→ gui.log 的 START 行。敏感任务用后清理这三处，
  或避免经 send 传密。
- **并发**：同一台 Mac 同时只允许跑一个 pt.py（本地锁已加，检测到活进程即拒绝）；
  并发会互相覆盖 next_cmd、截断日志。
- **双桥同名**：create_task.ps1 与 create_task_elevated.ps1 默认同名 PtGuiBridge，
  `/f` 重注册互相覆盖；换机部署时用参数指定不同 TaskName。
