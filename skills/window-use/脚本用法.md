# 脚本用法 — 驱动命令表 · 调用姿势 · 部署 · 校准

## 两种调用姿势

**本机直跑**（agent/人就在那台 Windows 上）：
```
python win_gui_driver.py shot s1                # 命令走 argv，跑完即退
python win_gui_driver.py crop zoom 100 900 400 1000
python win_gui_driver.py click 960 540
python win_gui_driver.py script t1_place.py     # 执行 <AUTO>/scripts/ 下的应用脚本
```
注意：本机从带控制台的终端跑会占一个终端窗口；长期无人值守建议同样用 `pythonw`。

**Mac 远程遥控**（先完成一次性部署，见下）：
```
remote/pt.py send shot s1                       # 重写 next_cmd.txt → 触发计划任务 → 轮询 gui.log
remote/pt.py step w01.py [shot]                 # ★原子步进一轮: push 脚本 → send 执行 → pull 截图
#   ⚠️ 慢动作（软件冷启动/长等待）加大轮询预算：--timeout 是全局参数，必须放在 step/send 子命令
#   **前面**：`remote/pt.py --timeout 480 step x.py`；写在子命令后面会被当成位置参数吞掉。
remote/pt.py push t1_place.py                   # 上传脚本到 <AUTO>/scripts/
remote/pt.py pushdir apps                       # 整目录上传（部署应用包）
#   ⚠️ pushdir 保留「传入目录之下」的相对路径：必须在 skill 根目录 pushdir apps（整体），
#   才会落到 <AUTO>/apps/<包名>/…；只 pushdir apps/<包名> 会剥掉前缀、把文件散在 <AUTO> 根（2026-10-25 实付）。
remote/pt.py pull s1 zoom                       # 拉截图到 ~/.zcode/window-use/shots（skill 外，永不落 skill 目录）
remote/pt.py gc                                 # 手动归档截图目录（超 200MB 打包 tar.gz）
remote/pt.py log 20                             # 看驱动日志
#   截图目录每轮 pull 后自动归档（阈值 WGUI_SHOTS_MAX_MB，默认 200MB；最旧优先，
#   先打包 tar.gz→回读校验→再删原图，证据不丢）。手动预演:
#   python3 scripts/shots_gc.py --dir ~/.zcode/window-use/shots --dry-run
```

## 原子步进循环（标准节奏，两种场景通用）

一次触发 = **一个原子动作 + 一次验证**，循环推进（粒度按 app 包粒度表，
如 cisco-pt：连线一条/次、CLI 一台/次）。远程场景每轮就是一条 `step`：

```bash
python3 remote/pt.py step w01.py     # push 脚本 → 触发执行 → 自动拉回截图
# 看图确认 → 通过才 step 下一个；FAIL 就地停，按 SKILL.md"失败处理阶梯"走：
# 取证（error_*.png/全屏）→ 查坑（速查表 + grep 坑文件，命中按文档解法不自创）
# → 净场（单实例断言 + 双 esc）后才允许重试同一个动作，一次只改一个变量
```

约定：动作脚本最后一张截图与脚本同名（脚本末尾 `ptlib.shot("w01")`），step 据此自动拉回。
多条同构动作（如连 12 条线）= 写 w01…w12 一组小脚本**逐个 step**，绝不 for 循环塞进
一个脚本。代价是每次触发 ~15s 驱动冷启动，换来：每步有截图证据、失败可归因、爆炸半径
一个动作。Lab4 实证：多动作脚本中途失败既查不了因，还污染现场；拆成单步后同一批动作
5/5 全成（踩坑清单.md 公#21）。本机直跑同理，只是把 step 换成
`python win_gui_driver.py script …` + 看自动存的截图。

## 驱动命令表（win_gui_driver.py）

| 命令 | 参数 | 说明 |
|---|---|---|
| shot | name | 全屏截图 → `<AUTO>/shots/name.png` |
| crop | name x1 y1 x2 y2 | 区域 2x 放大截图（开眼校准用） |
| click / dclick / rclick | x y | 左键/双击/右键（主屏像素坐标） |
| move | x y | 移动鼠标（悬停展开提示） |
| drag | x1 y1 x2 y2 | 拖拽 |
| press | key | 单键（enter/esc/delete/shift…） |
| type / typeln | text | 键入文本（typeln 补回车）。**裸打字有丢字符/IME 风险，优先剪贴板**；遇非 ASCII 记 WARN 仍执行，中文/符号一律 paste |
| focus / maximize | — | 目标窗口（WGUI_TITLE_RE 匹配）置前/最大化 |
| findtpl | tpl out | 模板找图（需 opencv），结果写 `<AUTO>/tpl_result.txt`；输出路径传 `-` 时不落盘只回显 |
| script | fname | 执行 `<AUTO>/scripts/fname`，**驱动全局注入脚本环境** |
| winlist | — | 枚举顶层窗口 → winlist.txt（取证） |
| clip | text | 写剪贴板（@/中文等特殊输入的基础设施） |
| paste | x y text [shot] | 坐标点输入框 → ^a → ^v。对话框/自绘编辑框专用；全程不碰窗口句柄（踩坑清单.md 公#17） |
| console | mark | 开新控制台并打标题标记，之后按标记定位/发键（踩坑：标记没打前按差集找，见 apps/cisco-pt/踩坑.md 控制台相关节） |
| raise | title子串 | 目标窗口顶到 z 序顶层再聚焦——坐标点击前必调（踩坑清单.md 公#16） |
| menu | rx ry ix iy [shot] | 原子菜单操作：右键→截图取证→点菜单项，同一命令内完成（踩坑清单.md 公#18） |
| svcwait | state [svc] [timeout秒] | 轮询服务真状态到 state(RUNNING/STOPPED)，基于 sc query（踩坑清单.md 公#20）；svc 默认 MySQL80、timeout 默认 120s |

- 每条命令前驱动自动 `mouseUp` 复位左键（防失败 drag 卡键）。
- gui.log 记 `START/DONE/FAIL <cmd>`（行带日期前缀，超 5MB 轮转为 gui.log.old）；
  FAIL 附 traceback + 自动存 `error_<cmd>_<HHMMSS>.png`（时间戳命名，不再互相覆盖）。
- v2 辅助库（script 注入脚本里同样可用）：`set_clip / find_window / win_titles /
  wait_new_console / raise_topmost / targeted_find / paste_at / atomic_menu /
  svc_state / svcwait / nags_click`——用法见函数 docstring；定向 UIA 查询用
  `targeted_find(win, control_type, name_sub)`，**不要对大窗口做全树遍历**（踩坑清单.md 公#15）。
- ⚠ 近名陷阱：**脚本注入环境里没有 paste(...)，只有 paste_at(...)**——命令行的 `paste`
  是驱动子命令，不是脚本函数。脚本里写 paste(...) 会 NameError
  （踩坑清单.md 公#39 案发现场，特意在此立牌）。

## script 注入协议（应用脚本怎么写）

`script` 用 `exec(code, dict(globals()))` 执行，脚本里直接可用：
`click/dclick/rclick/move/drag/press/type/typeln/shot/crop/focus/maximize/findtpl/log`、
`AUTO`（工作目录）、`TITLE_RE`、以及 `pyautogui/pywinauto/mss` 等已导入模块
（pywinauto 已在驱动 import，注入环境可直接用 `pywinauto` 名字）。

⚠ **模块桥接**：驱动自注册为 `sys.modules['wgdrv']`——应用库（navlib/sqllab 等）内部
`import wgdrv` 桥接驱动原语。注入函数只对脚本命名空间可见、对 import 进来的模块不可见，
这就是 wgdrv 存在的原因。

应用包脚本的标准开头：
```python
import sys; sys.path.insert(0, AUTO + r"\apps\cisco-pt")
import ptlib as pt
```
（ptlib 在自己的模块命名空间里，写自己的 `ptlib.log`；主线 START/DONE 仍由驱动记。）

## 新 PC 部署清单（一次性）

1. `pip install pywinauto pyautogui mss pywin32`（findtpl 另需 `opencv-python`；pillow 随 pyautogui 自动装上——截图的 PIL 依赖来自 pyautogui；mss 本身零依赖）
2. 驱动放到固定目录，如 `C:\Users\<user>\ptauto\win_gui_driver.py`；
   按需设环境变量 `WGUI_AUTO`（默认 `C:\Users\master\ptauto`）、`WGUI_TITLE_RE`（默认 Packet Tracer）
3. **本机场景**：到这一步就能用了——`python win_gui_driver.py shot test` 验证
4. **远程场景**：改 `remote/create_task.ps1` 顶部三个变量（任务名/pythonw 路径/驱动路径；
   也已支持参数传入，保留默认值），在 PC 上执行一次。验证全链路：
   `python3 remote/pt.py send shot verify1`（一条命令自动完成 投递+触发+轮询+拉图）。
   ⚠ 不要再手工 `schtasks /run` 验证——next_cmd.txt 读后即删，无投递命令时
   /run 只会在 gui.log 记一条 FAIL parse
5. Mac 端 `remote/pt.py` 的默认参数即当前 PC；换机器用 `--host/--task/--auto/--remote-base` 覆盖

## 开眼校准（新软件/新布局）

1. `crop` 放大看区域，读出目标控件的**当前分辨率像素**
2. `click x y` 试点 → `shot` → 拉回确认命中
3. 命中后按元素停靠方式换算成锚点规格（下节），写进应用包动作库的 COORDS（ptlib/navlib/sqllab/spsslib/acclib 各自的坐标表）

## 坐标体系：比例 + 锚点（换分辨率不用重校）

绝对像素换屏幕就作废；一律存"规格"，运行时按实际分辨率解析（`ptlib.resolve`）：

| 锚点 | 格式 | 含义 | 适用 |
|---|---|---|---|
| `r` | `("r", rx, ry)` | 屏幕宽高比例 0..1 | 画布内容、随窗口拉伸的区域 |
| `bl` | `("bl", px, dy)` | 左缘像素 + 距底像素 | 贴底停靠的工具条/面板（固定像素大小的图标，纯比例会脱靶） |
| `c` | `("c", dx, dy)` | 屏幕中心偏移像素 | 居中弹出的对话框 |
| `tl` | `("tl", px, py)` | 左上固定像素 | 贴顶工具条 |

**新 PC/新分辨率首跑 `ptlib.probe()`**：把坐标表逐个画十字准星存一张图（不点击），
拉回对照，偏了改数字。同 DPI 下图标像素大小不变，所以 bl/c 类锚点跨分辨率天然成立；
`c` 类"是否真居中"未验证时 probe 一眼便知。
