# 踩坑清单【公共坑】— 本机/远程任何 Windows GUI 自动化都成立

坑分三级，本文件只收第一级：
- **公共坑**（本文件，公#1-公#40 + 公S1-公S7 + 公E1-公E7 + 公M1-公M12，共 70 条编号坑）：换软件、换本机/远程场景都成立
- **远程场景坑** → [remote/远程坑.md](remote/远程坑.md)（§1-§11）
- **应用私有坑** → `apps/<软件>/踩坑.md`（现有：cisco-pt、navicat、sqldeveloper、wps、excel、ms-project、spyder、quartus（无私有坑文件，坑在公E/公M 段）、access、oracle-db、spss、devcpp、huawei-ensp、wireshark）

**失败时怎么用这份清单**（铁律"撞墙先查坑"的落地，规则全文见 SKILL.md"失败处理阶梯"）：
1. 先在 SKILL.md 的"坑点速查表"按症状定位坑号——30 秒；
2. 或直接 grep（skill 根目录下，关键词取报错原文片段/症状动词/界面元素名，一次给 2~3 个）：
   `grep -rn -i -E "关键词1|关键词2" 踩坑清单.md remote/远程坑.md apps/*/踩坑.md`
3. 命中 → 读该条全文，**按解法做，不自创**；同一症状失败两次还没 grep 过 = 违规。

## 输入

### 公#1 中文 IME 拦截按键
- **症状**：Enter 落进控制台变成汉字"平"；type 打的字缺笔画或错字。
- **解法**：动作前按一下 Shift（切 EN）；回车用 pywinauto `send_keys("{ENTER}")`；
  **文本一律剪贴板粘贴**（`set_clip + ^v`），不裸打字。

### 公#2 裸打字丢字符/吃特殊字符
- **症状**：`PC12` 打成 `PC2`；`(030)` 打成 `030`。
- **解法**：一切输入走 `set_clip + ^v`；输入框先三击全选再贴，避免追加到占位文本后面
  （网格单元格的 `NULL0001` 事故）。

### 公#3 失败的 drag 卡死左键
- **症状**：一次 drag 中断后，所有 click 都被当成 drag（按下拖走），界面乱点一气。
- **解法**：每条命令前 `pyautogui.mouseUp(button='left')` 复位（驱动已内置在主入口）。

## 定位

### 公#4 DPI 未声明 → 坐标全错
- 高 DPI 屏上不声明进程 DPI aware，截图和点击坐标系不一致，点击系统性偏移。
- 驱动入口已内置 `ctypes.windll.user32.SetProcessDPIAware()`，自定义脚本别丢这行。

### 公#5 应用内嵌对话框在 UIA 里被拍平
- **症状**：屏幕上明明开着对话框，`Desktop.windows()` 枚举不到，按标题匹配永远失败。
- **原因**：VS shell/WPF/Qt 应用的很多"对话框"是主窗口树内的子面板，不是顶层窗口。
- **解法**：在主窗口 `descendants(control_type="Button"/"MenuItem")` 里按名称+矩形位置找；
  找不到就退化用**截图定出的像素坐标**（居中小模态尤其如此）。

### 公#6 UIA Name ≠ 显示文本
- 控件显示"选择"，`window_text()` 返回空或别的。**先取证再写匹配**：
  `winlist`、`print_control_identifiers` dump、截图，三者对齐后动手。

### 公#7 菜单操作：截图 + 坐标点击 > 加速键/方向键导航
- 加速键跨版本/跨语言不可靠；方向键序列会焦点漂移、猜错顺序点到危险项。
- 菜单打开后（pythonw 不抢焦点，菜单能跨命令保持打开）截图读位置，鼠标坐标点击；
  Qt 应用的 QMenu 可用 UIA 按名精确点（见 ptlib.menu_click）。
- **【修正】**：'菜单能跨命令保持打开'并非总是成立——公#18/公#30 实测菜单不跨驱动轮次；例外见公S7（Wireshark Qt 菜单实测跨轮）。依赖此假设前先读公#18。

## 状态

### 公#8 模态对话框静默阻塞一切
- **症状**：菜单打不开、按键消失、命令超时——其实有个弹窗在等按钮。
- **解法**：每阶段先截图；发现弹窗用 UIA/坐标点掉再继续。

### 公#9 控制台分页器吞输入
- `--More--` 之类分页提示会把后续整行输入当翻页键吃掉。
- **解法**：长输出后先贴 `q` 或回车冲掉分页再发下一条。

### 公#10 强杀进程的连环后果
- `taskkill /F` 后重启会弹"恢复文件"对话框阻塞一切 → UIA 点掉（读按钮全名，别猜加速键）。（Excel 另有更彻底解法：删 %AppData% 恢复目录与 UnsavedFiles，见 apps/excel/踩坑.md 2026-10-31 条）
- 向导类程序失败运行会留下实例 + 文件独占锁 → 启动前枚举窗口逐个关闭，断言实例数为 1。

### 公#11 冷启动时间差异
- 脚本在应用就绪前找控件，随机失败。**轮询**特征控件/产物文件出现，不固定 sleep。

### 公#11b Qt 弹出菜单不接受"瞬移点击"（Lab4 实战新增）
- **症状**：菜单弹出、坐标算得完全正确，`pyautogui.click(x,y)` 点上去菜单毫无反应（不关闭也不选中）。
- **原因**：Qt 弹出菜单忽略鼠标瞬移（teleport click）；必须先把光标**移动到菜单项上**触发 hover，再按下-释放。
- **解法**：`moveTo(x, y, duration=0.25)` → sleep → `mouseDown(); sleep(0.12); mouseUp()`。配套验证：点击后**扫描菜单是否从屏幕消失**——还在=点击落空，自动重点；菜单消失也不代表一定选中（可能点空关闭了菜单），关键操作要做端到端结果验证（如连线后检测两设备间是否出现线段）。

### 公#11c 提权（管理员）窗口：UIA 看不见、合成点击被吞（Lab4 实战新增）
- **症状**：屏幕上明明开着的窗口，UIA `Desktop().windows()` 枚举不到；`pyautogui.click` 点它的按钮毫无反应；截屏却看得见。
- **原因**：窗口以管理员权限运行（cmd 标题带"管理员:"），UIPI 隔离把非提权进程的 UIA 枚举和合成输入静默丢弃。
- **解法**：关闭它不走 GUI——SSH 会话持有管理员令牌，`taskkill /F /IM 进程名`（Git Bash 加 MSYS_NO_PATHCONV=1）直接生效。预防：被自动化的应用别用管理员身份跑。

### 公#11d 目标应用开了两个实例 = UIA 与点击全面错乱（Lab4 实战新增）
- **症状**：菜单扫不到、点击落空、截屏内容和 UIA 看到的对不上——各种灵异。
- **原因**：同一路脚本面对两个应用实例：UIA 枚举混入两边的窗口，坐标点击落在**前台那个实例**（可能是空白/另一个文档）。
- **解法**：开工前 `tasklist | grep -i 应用名` 确认单实例；多余的全部 taskkill（**先保住有未保存进度的那个**——进度只存在内存直到 Ctrl+S）；脚本代启动应用前也先查重。

### 公#11e 脚本异常退出会留下"现场"污染后续脚本（Lab4 实战新增）
- **症状**：一次脚本崩了之后，后面所有脚本的同类操作全部诡异地"成功却无效"。
- **原因**：崩溃时弹出中的菜单、打开中的对话框、挂起的半截连线都留在界面上，后续点击被它们吸收或误触。
- **解法**：每个脚本**开头连按两次 esc** 清场；失败重试前也先 esc。诊断"点击无效"前先截全屏看有没有残留弹窗。

## 纪律（从两次实战项目里反复验证）

### 公#12 截图闭环是最高法则
- 每个动作后立刻截图查看。90% 的"按键没反应"一张截图就能定位（焦点在别处/弹窗挡住/菜单没开）。

### 公#13 平行通道验证 ground truth
- 截图给人看，配置文件/数据库/API 验证真相。GUI 显示成功 ≠ 真成功。

### 公#14 一次只改一个变量
- 每轮迭代只调整一个假设（匹配方式/等待方式/坐标），否则无法归因。
- 反复失败先**查坑**（SKILL.md 速查表 + grep 坑文件，命中按文档解法不自创），再写**只读诊断**
  （winlist/UIA dump/截图）跑一次，基于证据修，不猜测式修改。阶梯规则见 SKILL.md"失败处理阶梯"。

### 公#15 大窗口全树 UIA 遍历超慢（还会连锁堵死其它 UIA 调用）
- **症状**：对服务管理器(约 200 行列表)做 `print_control_identifiers(depth=7)` 或
  `descendants()` 跑几分钟不返回；期间其它 UIA 枚举也被堵住。win32 后端看 MMCMainFrame
  全是无类型元素，什么都看不见。
- **解法**：只做**定向查询** `win.descendants(control_type="Hyperlink"/"ListItem"…)`（秒级）；
  需要了解结构时按 control_type 分批 dump，不做 depth=7 全量。远程场景下全树遍历还会
  占住驱动实例，让后续 /run 被 IgnoreNew 静默跳过（见 remote/远程坑.md §4）。

### 公#16 手算像素坐标会漂移；点 UIA 元素中心才是稳定锚点
- **症状**：按截图算好的坐标连点三次都没触发；工具栏图标增删一次，整个客户区坐标平移几像素。
- **真实案例**：点 (160,153) 落在"停止"链接 hitbox (136,151)-(160,168) 的右边界像素上，从未生效。
- **解法**：能被 UIA 暴露的控件（Hyperlink/ListItem/Button）用 `targeted_find()` 定位后
  `el.click_input()` 点元素中心；实在只能用像素时：点击前 `raise_topmost()` 把目标窗口顶起
  （否则点在叠在上面的别的窗口里），点击后立刻截图确认落点。列表 type-ahead 前必须先真实
  点击**某一行**让列表拿到键盘焦点——点空白区不切换焦点，type-ahead 无效。

### 公#17 模态对话框期间对父窗口 set_focus 会抢走对话框焦点
- **症状**：往对话框输入框"粘贴成功"，回头一看是空的。
- **原因**：对话框存在时父窗口无法激活，set_focus 把键盘焦点从输入框抢走，随后的 ^v 落空。
- **解法**：点输入框 → `set_clip` → `^a` → `^v`，全程不碰任何窗口句柄（驱动 `paste_at`）。

### 公#18 上下文菜单不保证跨命令保留 → 菜单操作原子化
- **补充修正 公#7**："菜单能跨命令保持打开"并非总是成立——周期弹窗/焦点变化会把菜单关掉。
- **解法**：右键和点菜单项放进**同一条驱动命令**（驱动 `atomic_menu`：右键 → 截图取证 → 点菜单项）。
  模态对话框则相反：会一直留着等下一命令处理，不用原子化。

### 公#19 周期弹窗/登录墙打断一切（Navicat Lite 订阅过期等）
- **症状**：免费软件每 60~90 秒弹"会话已过期"，偶发全屏登录框挡住一切操作；点击间隙又弹出来。
- **解法**：向用户要账号，GUI 里"点击输入框 → ^a → ^v"填表登录一次可大幅减少弹窗，但 Navicat Lite 登录后仍会周期弹（apps/navicat/踩坑.md #2），nags_click 自愈循环仍需常开；
  登录前用**重试循环自愈**：每轮先点掉已知弹窗按钮坐标（无弹窗点空白无副作用）再执行动作，
  8 轮每轮截图，被打断就靠下一轮恢复（驱动 `nags_click` + script 注入循环）。

### 公#20 服务启停报 1053 ≠ 失败；以 sc query 为准
- **症状**：`net start`/服务对话框启动报"错误 1053: 服务没有及时响应启动或控制请求"。
- **原因**：SCM 默认等 30s；慢服务（如 mysqld 的 InnoDB 初始化偶发 90s+）超时被报错，
  但服务进程仍在后台继续启动。
- **解法**：报错后继续 `svcwait("RUNNING")` 轮询真状态（驱动内置 `svc_state/svcwait`，
  基于 `sc query` 平行通道）；报错截图反而是实验报告的好素材。动手前先旁路摸底目标状态
  （SHOW DATABASES / sc query / 文件存在性），发现以前实验的残留同名库先清理再建。

### 公#21 原子步进：一次触发只做一个动作（Lab4 定为铁律）
- **事故**：一个脚本里连续连线多条——第一条往往成，之后 B 端端口菜单必现不弹（A 端
  100% 正常），失败还污染现场，后续脚本全部诡异地"成功却无效"；同样的连线拆成
  "一次触发一条线"后 5/5 全成。
- **规则**：一次驱动触发 = **一个原子动作** + 一次截图验证，验证通过才发下一个。
  粒度按 app 包粒度表（cisco-pt：连线一条/次，CLI 一台/次，放设备可一批但逐台核对）。
- **为什么**：① 多动作脚本中途失败无法归因，也没有失败瞬间的截图；② 上一步的残留状态
  （未冷却的菜单、半截连线、焦点）会吸收下一步的点击，单步触发自带 ~15s "冷静期"；
  ③ 失败重试的爆炸半径只有一个动作。
- **代价**：远程场景每次触发多 ~15s 驱动冷启动。相比排障时间，这是最便宜的保险。
- **反模式**："都写一个脚本里省事"——省下的是分钟级，赔进去的是小时级排障 +
  无法归因的现场污染。

### 公#22 截图陈旧帧:像素会说谎,API 才是真相(Lab5 实付,windowpc)
- **症状**:截图显示完全错误的现场(几天前的旧窗口、旧拓扑),窗口枚举(winlist/EnumWindows)
  却只有一个正确窗口;脚本点击实际全部落对——追了半小时"幽灵窗口",其实是截图在说谎。
- **原因**:该 PC 有残帧虚拟显示器,mss 的 `monitors[1]` 随机命中它;且远程会话合成器不主动重绘,
  被遮挡/无鼠标事件的区域停留在旧帧。mss 屏幕拷贝、PrintWindow(Qt 应用只出局部渲染)都不可信。
- **解法**:① 抓 `monitors[0]`(整个虚拟桌面);② **截图前强制重绘**:最小化再还原目标窗口
  (ptlib.repaint/fshot);③ 现场真伪用 API 层验证(EnumWindows/UIA/文件 mtime),不信像素。
- **推广**:任何机器上"截图与窗口枚举矛盾"时,先怀疑陈旧帧,再怀疑多实例。

### 公#23 阶段完成立即保存(强杀=清零)
- **事故**:Lab5 放置+改名 10 台设备后强杀 PT 重开文件,15 分钟工作清零——一切只存在内存。
- **规则**:每个阶段(放置、连线、配置、抓包)跑完立即 Ctrl+S 并用文件 mtime 验证落盘;
  `shutdown`/`taskkill /F` 前必须先确认无未保存进度。

### 公#24 点击后立即截图 = 旧帧/空面板（Qt/自绘界面渲染延迟 ~1s）
- **事故**：Lab5 v2 抓包一整晚，几十张 PDU 面板截图全是空的或上一个事件的内容——
  脚本点行后 0.3~0.5s 就截，Qt 面板要 ~1s 才画完；切标签同理。误判成"点击没生效"，
  又去改坐标、换点击方式，越改越乱。
- **规则**：有状态变化的点击（选中行、切标签、开对话框）后 **sleep ≥1.2s 再截**；
  标签类控件点两次隔 0.8s。先排除渲染延迟，再怀疑坐标。
- **判据**：同一坐标偶尔成功偶尔空 = 时序问题，不是坐标问题。

### 公#25 截图存在 ≠ 截图有效：宣布"材料齐"前逐张裁关键区验收
- **事故**：Lab5 v2 六张 ARP/DNS 报文图当晚"拍完"，次日组报告时发现全是没开面板的全屏画布，
  被迫重新开机重拍——多花一轮完整的 PC 往返。
- **规则**：每批证据截图拉回后，立刻把**目标区域裁出来看一眼**（如 PT 的 PDU 面板区）
  再登记为"已拍"；按内容命名文件（见过 At Device/Layer 文本才叫 dnsreq_osi）。
- **推广**：所有"拍证据"类任务通用——自动化拍的图默认是嫌疑人，不是证人。

### 公#26 Mac 端 ssh 直发 Windows 命令：反斜杠被吃 + 路径转换（2026-10-20 MS Project 实付）
- **症状**：`ssh windowpc 'dir C:\Users\...'` 远端收到 `C:Usersmaster...`（反斜杠全丢）；
  `/query` 之类参数被 Git Bash 转成 `C:/Program Files/Git/query` 报"无效参数"。
- **原因**：Mac 本地 shell 对命令串做 MSYS 路径转换，且 ssh 默认远端 shell 会吞反斜杠。
- **解法**：复杂命令**首选写成 .ps1/.cmd 文件上传执行**（最稳，sqlcmd 类程序对正斜杠路径会报怪错）；
  次选 printf 管道：`printf 'dir C:\\path\\file\r\nexit\r\n' | ssh windowpc cmd`（管道喂 cmd，
  printf 里双反斜杠），输出 `| iconv -f GBK -t UTF-8` 转码；ssh 参数一律双反斜杠或正斜杠。
- **推广**：所有 Mac→Windows ssh 场景通用。

### 公#27 windowpc MS Project 2024 环境速记（2026-10-20 校准）
- 安装路径 `C:\Program Files\Microsoft Office\root\Office16\WINPROJ.EXE`，Project 标准版 2024 中文。
- 1920×1080 下已校准坐标：任务/资源/报表/项目 tab ≈ x=89/134/178/222 y=63；项目信息按钮 (246,110)；
  项目信息对话框开始日期输入框 (860,279)、确定 (1143,751)；新建-空白项目 (290,205)。
- 启动到可点"空白项目"需 ~25s；对话框/日期粘贴用 paste_at 稳定，日期格式"2026年3月2日"直接可贴。

### 公#28 MS Project 任务网格"插列"：自绘编辑器+布局漂移+静默失败三连（2026-10-20 实付 4 次尝试）
- **症状**：右键列标题→插入列→"键入列名"下拉里粘贴字段名不生效（无痕失败）；随后按旧坐标
  补点，焦点串到表头/别的单元格，还挂出日期下拉，esc 收不掉；连续 4 次才接近成功。
- **原因**（四因叠加）：① Project 任务网格列编辑器是自绘浮动控件，点击/粘贴/esc 的落点取决于
  内部焦点，截图不可见；② 网格布局每动一次整体漂移（插列=凭空多一列，右侧全移），拿旧截图推
  新坐标必脱靶；③ 粘贴打到无焦点控件是**静默失败**——不报错、界面正常，发现滞后 2-3 步；
  ④ 打包脚本（点→粘贴→回车一条龙）把前一步的静默失败放大成后续全打偏——违反原子步进。
- **解法**：
  ① 右键菜单本身可靠（菜单项坐标可复用：插入列菜单项实测命中）；
  ② "键入列名"下拉改用**键盘**：点编辑框后直接 `set_clip+ctrl+v` 一次（框已聚焦时有效），
     或更稳——方向键在列表中滚动定位字段名+回车，完全避开粘贴；
  ③ 任何网格内动作后**立即裁剪目标区验证**，验证不过不执行下一步；
  ④ 网格内悬挂的下拉用**点击远处空白格**收（esc 在此场景会串焦点，且模态对话框严禁 esc）。
- **推广**：一切"右键菜单→网格内嵌编辑器"类操作（Excel/Navicat 网格同理）通用。

## 远程静默安装软件（2026-10-20 Quartus II 13.0sp1 实战，编号 公S1-公S6）

### 公S1 BitRock 安装器从只读挂载卷直接跑 → "payload initialization failed"
- **症状**：QuartusSetup*.exe 在 PowerShell 挂载的 ISO 盘符里直接运行，秒退报"Installer payload initialization failed... corrupt downloaded file"，但 MD5 校验一致。
- **原因**：BitRock 初始化时要回读安装器自身路径，只读卷/挂载卷上失败。
- **解法**：先把 components 目录整份拷到本地磁盘（Copy-Item -Recurse），再从本地路径跑安装器。

### 公S2 SSH 里 nohup 后台进程 → SSH 会话一关就被杀
- **症状**：`nohup powershell ... &` 返回 launched，但进程消失、日志 0 字节，无任何报错。
- **解法**：长任务一律走 schtasks 计划任务（`/sc once /sd 2099-01-01 /st 00:00 /f` + `/run` 立即触发），与 SSH 会话完全解耦。

### 公S3 安装器需要 UAC → Start-Process 报"请求的操作需要提升"
- **解法**：schtasks 注册时加 `/rl HIGHEST //it`，任务进程即提权，无 UAC 弹窗（与 create_task_elevated.ps1 同原理）。

### 公S4 Transcript -Append 追加日志 → grep 旧标记误报完成
- **症状**：监听脚本 grep 日志里的完成标记命中了上一轮失败运行的旧行，提前返回。
- **解法**：轮询安装完成用**文件存在性探测**（如 `test -f <installdir>/bin/quartus.exe`），不用日志标记；或先删旧日志再启动。

### 公S5 注意：BitRock unattended 安装器 -Wait 会提前返回
- **症状**：安装器 fork 子进程后父进程退出，脚本继续走，实际安装还在后台跑。
- **解法**：后续步骤（验证/下一组件）以目标文件存在为准轮询，别信脚本顺序。

### 公S6 NSIS 安装器 GUI 逐页点击 → 走提权桥静默安装配方（2026-11-02 GSBrowser/数据管家实战，12s 装完零弹窗）
- **场景**：Mac 遥控装国产软件（浏览器/工具多为 NSIS：`file` 报 "Nullsoft Installer
  self-extracting archive"）。GUI 逐页点击费时且易被弹窗打断，静默安装一次成。
- **配方**（前提：桥 RunLevel=HighestAvailable，如 PtGuiBridge；`schtasks /query /tn <桥> /xml | grep -i runlevel` 确认，
  安装器写 Program Files/LocalAppData\Programs 的 UAC 就被桥的提权直接吸收，无弹窗）：
  1. Mac 端 `file xxx.exe` 探测 NSIS → 支持 `/S`；
  2. SFTP 上传 exe 到 PC **本地盘 home 相对路径**（公S6 附注：upload 相对路径落在 `~/`，与 ptauto 无自动关联，
     校验 md5 前先定位实际落点，别想当然按上传意图拼路径）；
  3. 桥 script 通道：`subprocess.Popen([exe, "/S"], stdout=DEVNULL, stderr=DEVNULL)`（公#32 纪律）+
     轮询候选安装目录出现（`%LocalAppData%\<名>`、`%LocalAppData%\Programs\<名>`、Program Files 两处）
     与 `p.poll()` 退出码，300s 超时兜底 shot 看现场（/S 被忽略弹 GUI 时截图即证据）；
  4. 启动验证：Popen 主 exe → tasklist 轮询进程 → sleep 6s 再 shot。
- **坑中坑**：安装器文件名 ≠ 产品名（GSBrowser_Setup_15.5.0.exe 装出来是 `数据管家.exe`，Electron 应用）。
  找快捷方式/验证进程一律按**安装产物真名**搜（先 `ls 安装目录` 看主 exe），按安装器名搜必落空；
  中文 exe 名 tasklist/grep 正常可用（Git Bash UTF-8）。

## 驱动进程自伤与诊断纪律（2026-10-20 Spyder 实战实付 ~50 分钟）

### 公#32 驱动脚本里对长活进程用 subprocess.run(capture_output=True) → 桥静默瘫痪
- **症状**：脚本永不返回，gui.log 停在 START 无 DONE；后续 send 全部超时，schtasks 触发"成功"但什么都不执行。
- **原因**：`run()` 超时后只杀了 shell，长活子进程（Spyder 内核、任何服务器类进程）还活着并握着 stdout/stderr 管道，父线程卡死在 communicate()。驱动是单线程 exec，一线程卡死 = 整个桥报废；旧驱动进程不退，新实例又起不来（LastTaskResult=2147946720）。
- **解法**：驱动脚本里跑长活进程一律 `Popen` + stdout/stderr **重定向到文件**（或 DEVNULL），绝不 `run()` 等它；
  需要判断"起没起来"就轮询产物文件存在性（连接文件 kfile、日志标记）。
- **恢复**：`taskkill /F /IM pythonw.exe`（驱动本体）→ `schtasks /run /tn <桥>` → 30s 后 gui.log 恢复滚动。

### 公#33 taskkill /IM 的误伤半径：同一运行时家族一起死
- **症状**：想杀卡死的测试内核（python.exe），`taskkill /F /IM python.exe` 后 Spyder GUI（pythonw.exe）也没了，界面全丢重新走首启流程。
- **原因**：GUI 与内核/脚本同属 conda python 家族，按映像名杀就是无差别；且杀内核会连带托垮依赖它的 GUI。
- **解法**：按 PID 杀（先 `tasklist /fi "IMAGENAME eq x.exe"` 查清哪个 PID 是目标）；杀之前截图确认桌面现状，
  接受"界面应用要重拉"的代价并把它排进后续步骤（重拉=重新处理首启弹窗）。

### 公#34 有 GUI 通道可用时禁止无头诊断——界面上的报错先读原文
- **症状**：Spyder 内核启动失败，红框报错就画在控制台面板上；却绕道 SSH 查进程列表、命令行复现、
  对比版本号，25 分钟没看过报错原文一眼，猜的三个原因（版本不匹配/防火墙/pip 污染）全错。
- **原因**：前一个场景（Mac CUA 输入全被拒）留下的"无头惯性"带进了输入完好的新环境；把"能 SSH"当成了"该 SSH"。
- **解法**：切到任何一台新机器，先验证输入通道（点一下、截一张），通道可用则**一切诊断从 crop 放大界面报错开始**；
  无头手段只用来做平行验证（公#13），不用来当主诊断路径。

### 公#35 多文档 GUI 软件第二次 Popen ≠ 同实例开新文档（2026-10-25 SPSS 实战，app 侧 SP#7）
- **症状**：第一轮跑完建好数据集/工程，第二轮再 `Popen([exe, file2])` 打开另一个文件，报"文件不存在/变量未定义"，
  仿佛第一轮白跑；`tasklist` 一看有 **两个** 该 exe 进程。
- **原因**：不是所有软件都像 Office/Notepad 那样把第二个命令行参数交给已运行实例；SPSS、部分 Qt/Eclipse 系
  默认每次启动都开全新实例，进程间数据集/会话互不可见。
- **解法**：对一个软件的实例模型没把握时，第一次对接就用 tasklist 数进程验证：Popen 两次 → 进程数变 2 即多实例软件，
  后续把多步任务**合并进一个文件一次执行**（或走窗口内"文件→打开"菜单），绝不靠再次 Popen 传递上下文。

## ModelSim 仿真批量生产（2026-10-20 EDA 任务2/3/4 实战新增，编号 公M1-公M8）

### 公M1 ModelSim 单实例模式：第二个 vsim -do 被静默吞掉
- **症状**：已有 GUI 实例时再 `vsim.exe -do new.do`（schtasks 返回成功），新 do 不执行，旧窗口纹丝不动。

- **症状**：`-t 10ns` 时 warning (vsim-3479)，tb 里 25ns 类激励被舍入。
- **解法**：一律 `-t 1ns`。

- **症状**：`CLK <= NOT CLK AFTER 5 NS` 让 run -all 永远跑（SSH 调 console 版直接卡死）。
- **解法**：do 里用固定时长 `run 200 ns`（按 tb 时长算好），不用 run -all。

### 公M4 改设计源码后跑"纯检查 do"→ 验证的是旧编译结果
- **症状**：修完 bug 重跑只含 vsim/examine 的 check.do，结果不变，误判修复无效。
- **解法**：检查 do 开头必须先 `vcom -work work xxx.vhd`（或先跑完整编译 do）。用 `vsim -c -do "vcom ...; do check.do"` 串联。

### 公M5 examine 采样时机不对 → "结果错误"假象（实为移位中间值）
- **症状**：多组激励的 tb（每组 265ns），按 245ns 步进 examine 商值，后几组显示怪数字，误判设计有 bug。
- **解法**：采样点必须落在每组 DONE 后的静止窗口内（起始 = 首组完成时刻，步长 = 组周期）；先 console 算准 tb 时序再写 check.do。

### 公M6 单字母快捷键也被中文 IME 拦截（公#1 补充）

### 公M12 ModelSim 强杀后重启白屏挂死：vsim.exe 存在但 ~5MB 不动、vsimk 不起
- **症状**：taskkill /f 后再启动，窗口一片白、日志停在 Loading；或 vsim 秒退（onerror quit）。

### 公#36 MSYS_NO_PATHCONV=1 必须写在远程命令字符串内部
- **症状**：本地 `export MSYS_NO_PATHCONV=1` 后 ssh 远程跑 `schtasks /create` 仍报 `无效参数 'C:/Program Files/Git/create'`——转换发生在远端 Git Bash。
- **解法**：`ssh windowpc "export MSYS_NO_PATHCONV=1; taskkill /f /im quartus.exe; ..."`——export 作为远程命令的第一句。


   **补充(2026-11-06 关机实战)**:关机/重启类命令三种姿势实测——本地 `MSYS_NO_PATHCONV=1` 无效(转换发生在远端 Git Bash);`cmd /c "shutdown /s /f /t 5"` 双层引号被吞、仅回显 banner 不执行(远§2/spss SP#15 同族);**最稳 = `powershell -c "Stop-Computer -Force"` / `Restart-Computer -Force`**,零斜杠参数。另注意:shutdown 失败时输出的是整屏用法帮助,`| tail -1` 只会看到无害的"旧版 API 关机"尾行,极易误判已执行——成败以 ping/SSH 探测为准。
### 公#37 schtasks 启动 GUI 程序的 bat 缺 `start` → 任务实例永久 Running，后续 /run 静默失败
- **症状**：bat 里裸写 `quartus.exe xxx`，cmd 阻塞等 GUI 退出 → 任务一直"正在运行"；之后每次 `/run` 回显成功实际被 IgnoreNew 跳过程序再也不启动（gui.log 无新 START）。
- **解法**：bat 里 `start "" "D:\...\quartus.exe" 参数`；每次 /run 前先 `schtasks /end /tn <任务>` + taskkill 兜底；程序起没起以 tasklist 窗口/进程为准，别信 schtasks 回显。

### 公#38 printf 写 bat 吃 `\a \b \f` 转义 → bat 内容变控制符
- **症状**：bat 里 `D:\altera` 写出来变成 `D:^Gltera^K.0sp1`（^G=BEL），程序不启动。
- **解法**：写 bat 一律 heredoc（`cat > x.bat <<XX ... XX`）+ `sed -i 's/\r$//;s/$/\r/'` 补 CRLF；或者本地 printf 单引号格式串里用 %s 传路径后管道给 `ssh 'cat > file'`。

### 公#39 驱动 script 注入的函数是 `paste_at`，没有 `paste`

### 公#40 · sed/文本替换批量生成脚本静默写坏（2026-11-04 eNSP 换 IP 重拍，3 次实付）
- **症状**：用 sed 替换模板里的 `sys.argv`/含引号文本来批量生成驱动脚本，产出的脚本语法错（argv 行变 `= 1600 PC4, ""`）或替换根本没生效（SKILL.md 索引行因引号不匹配静默 no-op、脚本内小写 crop 名没跟着改导致截图互相覆盖）。
- **原因**：模板含引号/特殊字符时 sed 匹配不可靠；替换后无校验直接推送执行。
- **解法**：参数化脚本一律 **heredoc 整段生成**（变量用 f-string/`$var` 内插），不用 sed 改代码；生成后本地 `python3 -m py_compile` + grep 关键行核对再 push；对文档的文本替换后必须 grep 验证命中数，不做静默假设。

### 公S7 · Npcap 免费版不支持 /S 静默安装（2026-11-05 win135 实战）

- **症状**：新版 Wireshark（4.7.x）报 "Unable to load Npcap (wpcap.dll)；WinPcap found instead"；dumpcap/tshark -D 全部无法列网卡。先 `npcap-x.x.exe /S` → 弹窗 "Silent installation is only supported in Npcap OEM"（免费版明确不支持静默）；WinPcap 的 `uninstall.exe /S` 也照样弹 GUI 向导，pythonw 卡在 Popen 等它退出。
- **解法**：走提权桥 GUI 点击安装，三轮原子步进：① WinPcap 卸载向导点 Uninstall→Finish；② Npcap 向导 I Agree→(选项默认：WinPcap API-compatible Mode 已勾)→Install→Next→Finish；③ 装完无需重启，`tshark -D` 立即可列接口。UIA 枚举不到 Wireshark 的 Qt 菜单（popup #32768 不出现），菜单导航改**截图读坐标 + 跨轮点击**（实测菜单跨驱动轮次存活，与公#18 相反的场景）。
- **附带坑**：curl 不带 -4 时走 IPv6，dumpcap 的 `host <IPv4>` 捕获过滤器全漏（pcap 0 字节）——抓包前先确认流量族，或强制 `curl -4`。
